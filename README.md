# Argus

快速、现代、信息丰富的 Windows 任务管理器。名字取自希腊神话中的百眼巨人阿尔戈斯。

## 架构

```
crates/argus-core   Rust 采集与操作层，不依赖任何 UI
  ├─ process.rs     NtQuerySystemInformation 一次拿全量进程/线程，差量计算 CPU 与 I/O 速率
  ├─ paths.rs       SystemProcessIdInformation 取映像路径（无需打开进程，非管理员也能拿到）
  ├─ meta.rs        后台线程解析文件描述、公司名、图标（PNG），按路径缓存
  ├─ system.rs      总 CPU（含内核时间）、每核 CPU、内存、提交、缓存
  ├─ hardware/      性能页的设备数据
  │   ├─ cpu.rs     型号、拓扑（每个逻辑处理器属于哪个核心、是性能核还是能效核）、缓存、虚拟化
  │   ├─ sensors.rs 一个 PDH 查询：整体与每核实际频率、ACPI 热区温度、RAPL 功耗（封装/核心/核显）
  │   ├─ battery.rs 电池类驱动 IOCTL：电量、充放电功率、电压、设计/完全充电容量、循环次数
  │   ├─ memory.rs  SMBIOS 解析内存条：速度、插槽、外形规格、DDR 代数
  │   ├─ disk.rs    物理磁盘：IOCTL_DISK_PERFORMANCE 取活动时间/速率/响应时间，型号/容量/SSD/卷，温度
  │   ├─ net.rs     网络适配器：GetIfTable2 取吞吐量，GetAdaptersAddresses 取 IP
  │   └─ gpu.rs     D3DKMT：各引擎利用率、专用/共享显存、温度、核心/显存频率（与任务管理器同源，无需驱动）
  ├─ details.rs     按需查询：命令行、用户、完整性级别、架构、优先级、版本
  ├─ services.rs    服务：SCM 枚举、启停、启动类型；名称与描述按用户界面语言从 MUI 读取
  ├─ startup.rs     启动项：注册表 Run 键与启动文件夹（解析 .lnk），启用/禁用写 StartupApproved，与任务管理器一致
  ├─ connections.rs TCP/UDP（IPv4/IPv6）端点与所属进程，断开 IPv4 TCP 连接
  ├─ filelock.rs    文件占用：Restart Manager；整批被拒时二分重试，隔离无法检查的文件
  ├─ actions.rs     结束进程 / 进程树（校验 PID+启动时间防 PID 复用，拦截关键系统进程）
  └─ privilege.rs   提权状态、SeDebugPrivilege、自身高优先级
src-tauri/          Tauri 2 宿主
  ├─ sampler.rs     采样线程：可见时按设定节拍，隐藏时每 5 秒
  ├─ shell.rs       托盘、全局快捷键、窗口显隐（同时通知 WebView2 停止渲染、释放内存）
  ├─ settings.rs    原生侧设置（快捷键、关闭行为），存于 %APPDATA%\dev.argus.taskmanager
  └─ commands.rs    IPC 命令；argus:// 协议提供进程图标
ui/                 SolidJS + TypeScript + Tailwind v4 前端（进程、性能、服务、启动、连接、设置）
  ├─ Trace.tsx      canvas 曲线：每次采样只画一次，随后由合成器把画布滑动一格
  └─ lib/motion.ts  动画偏好、Fluent 缓动曲线、进出场与“滑动一格”的关键帧
```

数据流：采样线程按固定节拍采样，经 Tauri Channel 推送整份快照给前端。
`argus-core` 的接口按"可以搬到独立特权服务里运行"来设计，为后续高权限方案留口子。

## 开发

需要：Rust（stable）、Node 22+、pnpm、WebView2（Win11 自带）、VS Build Tools。

双击 `start.bat`，或在终端里运行：

```bash
start.bat                  # 启动开发版：改前端即时热更新，改 Rust 自动重新编译并重启
start.bat ui               # 只在浏览器里跑界面（模拟数据），适合调样式
start.bat check            # TypeScript、Biome、rustfmt、Clippy
start.bat build            # 发布构建 target\release\argus.exe（build installer 生成安装包）
start.bat clean            # 清理增量缓存与发布产物；clean all 清空全部 Rust 缓存
```

`start.bat` 首次运行会自动安装前端依赖；每次启动前会结束上次会话残留的 Vite（占着 5173 端口）
和开发版进程。对应的 pnpm 脚本是 `pnpm app` 与 `pnpm check`，参数与 `start.bat` 一致。

**开发版与已安装版互不干扰。** 开发版通过 `src-tauri/tauri.dev.conf.json` 使用独立的标识
`dev.argus.taskmanager.devbuild`：单实例锁、设置文件、WebView2 数据目录、开机启动项都分开，
窗口标题和托盘提示显示“Argus 开发版”。否则托盘里常驻的 Argus 会让开发版一启动就把参数转交给它然后退出。

验证采集数据：

```bash
cargo run -p argus-core --example dump --release       # 进程
cargo run -p argus-core --example hardware --release   # CPU、内存、磁盘、网络、GPU
```

### 构建缓存

| | 优化前 | 优化后 |
|---|---|---|
| `target/` 总大小 | 7–9 GB | 约 2.2 GB（调试 1.4 GB + 检查 0.8 GB） |
| 调试版 `argus.exe` | 248 MB | 42 MB |
| 改动 Rust 后热重载（保存到新进程运行） | — | 约 5.7 秒，其中编译约 4 秒 |

做法：

- **调试信息**：依赖不生成调试信息（且以 `opt-level = 2` 编译，开发版运行流畅）；本项目代码只保留行号表，
  回溯仍可读。需要单步调试时用 `CARGO_PROFILE_DEV_DEBUG=full` 构建。
- **统一 `windows` 特性**：Cargo 只在同一次构建选中的包之间合并特性，单独构建 `argus-core`（例如运行示例）
  曾额外编译一份约 250 MB 的 `windows`。根 `Cargo.toml` 的 `[workspace.dependencies]` 列出全部特性
  （含 Tauri、tao、wry 启用的），所有构建共用一份。升级 Tauri 后用
  `cargo tree -p argus -i windows -e features` 核对。
- **检查与构建分开存放**：rust-analyzer（`.vscode/settings.json`）与 `pnpm check` 共用 `target/rust-analyzer`，
  后台检查不会占住构建锁拖慢热重载，检查产物也不会重复存两份。
- **清理**：`start.bat clean` 删除只会无限增长、又能快速重建的部分；升级依赖后用 `start.bat clean all`
  清掉旧版本残留。

还能更快的地方：链接目前约占每次重建的 1.6 秒（GNU ld）。改用 `rust-lld` 可降到约 0.3 秒，但在当前的
`x86_64-pc-windows-gnu` 工具链上会因 Tauri 与 MinGW 的两个清单重复而报错，见下方已知问题。

## 常驻与快捷键

- 默认关闭窗口时留在托盘；单击托盘图标或按 **Ctrl+Alt+Esc** 显示/隐藏，可在“设置”中更改。
- 隐藏时 WebView2 停止渲染并降低内存占用，采样降到每 5 秒一次，历史曲线不中断。
- 只允许单个实例：再次启动会唤出已运行的窗口。
- “设置”中可开启登录 Windows 时启动（带 `--hidden` 参数，静默进入托盘）。

## 性能基线

测试环境（i5-13500HX，20 逻辑处理器，约 550 个进程，发布构建，1 秒刷新）：

| 状态 | CPU（占单核） | 工作集 |
|---|---|---|
| 窗口可见，进程页，曲线动画关闭 | 约 4.3% | 约 500 MB（含 WebView2） |
| 隐藏在托盘 | 约 1.1% | 约 130 MB |

一次完整采样约 17–22 ms（含频率、温度、功耗、电池等传感器），其中内核枚举进程约 11 ms，GPU 引擎查询约 3 ms。

### 曲线动画

曲线沿时间轴匀速向左流动：每个点按采样到达的时间定位，图表右边缘是“现在减两个刷新间隔”，
最新的点总是已经画在右边界外，所以不用等下一个点，也就没有停顿。每次采样只在 canvas 上画一次，
之后只平移画布（连同悬停标记）。“设置 > 动画 > 曲线动画”提供四档：

| 模式 | 怎么动 | 帧率（165 Hz 屏幕） | 合成开销 |
|---|---|---|---|
| 流畅（默认） | 每个图表一条线性合成器动画，亚像素、每次刷新都动 | 跟随屏幕刷新率（165 帧/秒） | 进程页约 90 ms/秒，逻辑处理器视图约 125 ms/秒（约单核 9%–13%） |
| 均衡 | 同上，但所有图表按同一个时间网格分步，步长是刷新周期的整数倍 | 约 60 帧/秒且帧间隔均匀（165 Hz 时为一半，约 83） | 约一半 |
| 省电 | 共享定时器，每次整像素移动 | 进程页约 6 帧/秒，性能页约 16 帧/秒 | 约单核 1% |
| 关闭 | 每次采样跳一格 | 1 帧/秒 | — |

设置里显示的帧数是实测的屏幕刷新率：取 60 帧的间隔（去掉跳帧）求平均，再对齐到常见的标称值；
窗口重新获得焦点、换到其他缩放比例的屏幕时以及每 30 秒重测一次。流畅模式本身不依赖这个数，合成器总是按屏幕刷新。

合成开销取自 Chromium 跟踪中 GPU 进程与渲染进程合成线程的耗时；同一时段直接测 CPU 占用
波动极大（测量时机器上另有占用多个核心的负载），不作为依据。流畅与均衡模式下，帧之间主线程没有工作。

几个关键点：

- **不要用圆角容器裁剪动画元素**：任何带圆角又 `overflow: hidden` 的祖先，都会让合成器每帧为每个移动图层
  多做一次遮罩绘制。去掉这些裁剪后，逻辑处理器视图（31 个图表）的开销从约 94% 降到 28%（同一时段测得）。
  现在圆角卡片不裁剪内容，图表用自己的矩形裁剪；性能页的详情卡片里另放一个方角的滚动容器。
- **画面只能在定型后出现**：平滑曲线在某点的弯曲取决于它后面的点，所以一段曲线要等后一个采样到了才定型。
  右边缘落后“现在”两个刷新间隔（落后一个间隔时，最右一段会在每次采样时重新弯一下），左边缘外多画两个点。
- **虚线不爬动、尖峰上也均匀**：canvas 自带的虚线从路径起点按长度排，最旧的点一移出就整体错位、沿线爬动；
  按横向位置切（竖条裁剪）又会让陡峭的尖峰几乎成实线。现在由 Argus 自己把曲线展平成约 1 像素的小段、按长度切出虚线，
  并记住每个采样点在虚线图案中的位置，重画时让已经在屏幕上的点保持原位。
  同时每次重画的画布原点落在时间轴的整像素上，相邻两次重画逐像素一致（只差整体平移）。
- **共用帧**：均衡模式下各图表的分步若各自起算，帧数会叠加（20 个图表时 139 帧/秒）；对齐到同一网格后稳定在刷新率的一半。
- **每核小条也连续移动**：每根条的填充是一个真实元素（不是伪元素，Chromium 在主线程执行伪元素的过渡，
  实测每秒约 40 次重绘），在合成器上用一个刷新间隔从当前高度线性移到新值，下一个采样到达时正好到位。
- **调整窗口大小时的斜线**：Windows 11 会把窗口裁成圆角。WebView2 把页面画在一个半透明的子表面上
  （Chromium 的分层输出窗口 `Intermediate D3D Window`），它伸进了窗口底部的两个圆角。窗口尺寸变化时，
  DWM 处理圆角裁剪的快速路径偶尔会把这种表面沿客户区对角线多混合两次，闪出一条亮线；画面本身没有被拉伸。
  在只含 WebView2 的最小窗口里能复现；改成直角、让 WebView 避开底部圆角（留边 9 像素以上）、
  或让它的可见区域不是矩形，白线都会消失，换 Mica 或不延伸边框则没有影响。
  这条快速路径只用于可见区域是普通矩形的子窗口，所以窗口尺寸一开始变化（`WM_WINDOWPOSCHANGING`，
  拖动、贴靠、最大化、改 DPI 都经过这里），Argus 就给 WebView 的容器窗口设置一个只少了左上角 1 个像素的区域：
  那里是透明的页面背景，Mica 照常透出；DWM 改走通用路径，整个窗口只有圆角抗锯齿的几个像素差几级亮度。
  通用路径每帧多一点合成开销（录制状态下 DWM 的 GPU 占用约 1.1% → 1.6%），所以尺寸停止变化 300 毫秒后撤掉区域，
  平时不付出这份开销。见 src-tauri/src/shell.rs 的 `guard_resize_seam`。
  验证：用 Windows.Graphics.Capture 录窗口，逐帧检查客户区对角线（白线总在这条线上），每秒约 50 帧，
  与调整大小时窗口内容变化的频率相当。不设区域时每次 32–48 帧有白线；设置后为 0（含从左边缘拖动、快速拖动）。
  常速拖动的录制包含区域加上和撤掉的时刻，相邻帧的整体亮度变化最大 0.04/255，没有闪烁。
- 自动缩放的纵轴（磁盘、网络、功耗）在峰值离开窗口后逐步回落，不会整张图突然跳变。
- 界面动画（切换页面、菜单、对话框、滑动的选中标记）只在操作时播放一次，可单独关闭；默认都跟随 Windows 的“动画效果”开关。
- 暂停刷新时曲线停在最新数据处；窗口隐藏或被完全挡住时 WebView2 停止渲染，动画也随之停止。

窗口不使用 Tauri 的 `transparent: true`。它靠旧版 `DwmEnableBlurBehindWindow` 让整个窗口按透明窗口合成，
拖动时每次移动都更贵：模拟拖动测得超过一帧（165 Hz）的移动占 12–19%，普通 Win32 窗口为 8–10%。
现在改为 `DwmExtendFrameIntoClientArea` 把 Mica 延伸到客户区，只让 WebView 背景透明（`backgroundColor: #00000000`），
窗口本身保持不透明，拖动开销与普通窗口持平，外观不变。

## 设计原则

- **安静的表格，响亮的脉搏**：只有顶部概况带使用大号数字和实时曲线，表格保持克制。
- **颜色只编码数据**：青色 = CPU（能效核为长春花蓝），紫色 = 内存，琥珀 = 磁盘与负载热度，绿色 = 网络，玫红 = GPU，黄绿 = 电池，珊瑚红 = 破坏性操作；选中和焦点使用系统强调色。
- **数字不抖动**：等宽数字，按显示精度排序，避免相近的行每秒互换位置。
- **点哪儿就是哪儿**：指针在列表上、菜单或对话框打开时，刷新只更新数值，不重新排序。
- **原生优先**：Mica 背景、原生标题栏（保留贴靠布局）、Segoe UI Variable、系统强调色。
- **动效回应操作，曲线连续流动**：切换页面、打开菜单和对话框有过渡，选中标记在选项之间滑动；
  曲线按时间轴匀速流动，默认跟随屏幕刷新率，由合成器驱动，主线程不参与。
- **键盘可用**：Ctrl+1–6 切换页面；↑↓ 选择，←→ 折叠展开，Enter 详细信息，Delete 结束（Shift+Delete 跳过确认），Ctrl+F 搜索。

## 已知问题

- 在默认的 `x86_64-pc-windows-gnu` 工具链上，MinGW gcc 总会链接自带的 `default-manifest.o`，
  与 Tauri 的清单（manifest）重复：GNU ld 只警告并丢掉其中一个，`rust-lld` 直接报错。
  目前不影响运行，但提权功能需要可控的清单，也挡住了更快的链接器。建议改用 MSVC 工具链
  （`stable-x86_64-pc-windows-msvc` 加 VS Build Tools；可只对本项目生效，
  切换后需要一次约 5 分钟的完整重建）。
- 部分杀毒软件的脚本扫描（AMSI）会让 Windows PowerShell 偶发崩溃。`start.bat` 会重试，
  仍失败时跳过启动前清理并继续启动，不影响开发。
- 单实例插件的限制：若旧进程被强制结束后几秒内立即重新启动，可能出现两个实例。正常退出不受影响。
- 每核 CPU 只统计第一个处理器组（≤64 个逻辑处理器）。
- 刚启动的前 20 秒左右 WebView2 首次渲染与图标解码开销较高，之后回落到上表数值。
- 文件占用查询基于 Restart Manager：被受保护系统进程加载的文件（例如 ntdll.dll）无法检查，会单独标出；
  以某个文件夹为当前目录的进程也查不到（需要枚举句柄，属于 M5 的特权功能）。
- 多数服务的启停、所有用户启动项的启用/禁用需要管理员权限；没有权限时界面会明确提示。
- CPU 温度来自 ACPI 热区（`Thermal Zone Information` 计数器），多数笔记本上它跟随 CPU 封装温度，
  台式机主板上可能只是一个固定值或不存在。每核温度和 CPU 电压在处理器的 MSR 寄存器里，Windows 只允许内核驱动读取，留给 M5。
- 功耗来自 `Energy Meter` 计数器（Intel RAPL），需要较新的 Intel 平台；AMD 与部分台式机没有。GPU 电压取决于显卡驱动，NVIDIA 不提供。
