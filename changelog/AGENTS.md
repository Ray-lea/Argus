# 更新日志的代理须知

沿用仓库根目录的规则。内容与写法的规范见 `docs/development/release.md` 的“更新日志的内容”，发布步骤见同一页；这里只列容易做错的地方。

- 各语言文件的版本标题由 `pnpm release` 写入，不要手写。发布前预写条目时，标题只写 `## [X.Y.Z] - 日期`，不带比较链接（标签推送前链接 404，nightly 的外部链接检查会失败），由脚本补全。
- `zh-CN.md` 是源文本，其他语言的文件与它逐条对应，小节标题与语言名称在 `resources/changelog.json`。`pnpm release` 在其他语言的文件中写入由中文条目生成的草稿，推送标签前要全部译完；润色中文时同步修改各语言，用词与 `locales/<语言标签>` 的界面文案一致。
- 带标签的条目在繁中、日文写 `**标签**：`，其他语言写 `**Label**:`（冒号前不加空格）。
- `verify` 会拒绝仍含中文原文、小节与条目数不同或日期不同的译文条目。
- GitHub Release 正文完整显示中英文，顶部按 README 的写法链接其他语言的文件；应用与官网按界面语言显示对应译文。
- 整理条目时只写应用内用户可感知的变化，不写官网、CI、构建、测试和诊断日志的改动。以上一个发布为基线：本周期新增后又修改的功能并入功能条目，只描述最终的样子；“修复”只列上一个发布中就存在的缺陷。
- 外部贡献者的拉取请求在条目末尾写 `（@贡献者 #编号）` 并链接其主页与拉取请求。用 `gh pr list --state merged` 核对作者，以 GitHub 用户名为准，提交作者名可能不同；维护者自己的拉取请求不署名。
- 发布前准备中的独立审查：改动面大时交给 Codex 只读复审，审查报告与修复记录放在 `archives.local/<日期>/`。
