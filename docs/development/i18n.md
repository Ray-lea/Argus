# 多语言

本页说明文案目录的结构，新增、使用与检查文案以及增加语言的方法，界面语言、复数与区域格式的规则，并列出固定写法与常用界面术语。

## 文案目录

界面、托盘、原生错误和安装程序共用 [`locales`](../../locales) 中的文案。`zh-CN` 为源文案；`zh-TW`、`en-US`、`es-ES`、`de-DE`、`ja-JP`、`ko-KR`、`fr-FR`、`ru-RU` 在同一命名空间中提供译文。

用户可见的文字在所有语言的目录中维护；日志、panic 和注释使用英文。

### 键名

界面的键带文件名前缀，如 `settings.update.check`；`native.json` 中的键直接写作 `tray.quit`。两类键在同一个查找空间中解析，`native.json` 优先。因此两类键不能同名，例如 `native.json` 的 `startup.unavailable` 与 `startup.json` 顶层的 `unavailable`；`pnpm i18n` 会报告重名。

当前语言的目录中没有某个键时，先查找英文，再查找源文案；都没有时显示键名本身。原生层与界面的文案都经 `argus_core::i18n` 查找，回退的顺序相同。

### 安装程序的文案

安装程序的文案在 `installer.json`，打包时由 `scripts/lib/installer-locales.mjs` 转成 NSIS 的 `LangString`。钩子通过 `ARGUS_TEXT` 引用键。安装帮助进程接受各语言的 Windows LANGID，静态文本按字面显示路径中的 `&`。

### 更新日志

更新日志按界面语言各有一份（`changelog/<语言标签>.md`），由简体中文版逐条翻译而来，小节标题见 `resources/changelog.json`。

关于页显示编译进应用的对应语言版本。更新对话框优先显示该版本附带的对应译文；缺少时，繁体中文显示简体中文，其他语言显示英文，英文也缺少时显示中文。

官网与仓库说明文件的语言独立维护。

## 新增文案

新增文案时，用 `locale-keys.mjs` 一次写入全部语言：

1. 编写文案文件：一个 JSON，把每个新键对应到全部语言的文字。键以文件名开头，如 `tasks.explorer.note`。
2. 运行 `node scripts/locale-keys.mjs add <文案文件>`。

文案文件的写法：

- 用 `after` 或 `before` 指定新键在分组中紧挨哪个键；省略时放在分组末尾。
- 复数形式照目录中的写法给出对象，各语言所需的形式见[复数](#复数)。

命令在各语言文件的同一位置写入，随后运行 `pnpm i18n`。缺少任何一种语言的文字时不写入；检查不通过时，把文件恢复原状。

删除键时，运行 `node scripts/locale-keys.mjs remove <键>…`，从所有语言中删除。

译文遵循以下规则：

- 语言选项使用各语言的原生名称，方便在任意界面语言下识别。
- 路径、文件名、命令行参数、`Debugger`、`UseFilter` 和 JSON 的 `null` 等技术标识保留原文。
- 固定缩写、单位与常用界面术语按[术语表](#术语表)书写。

## 在界面中使用文案

GPUI 宿主注册文案目录后，用 `argus_core::tr!` 格式化带占位符的文字，用 `frontend::theme::label` 读取静态标签。动态键在绘制时按当前语言解析；日期、字节数和单位由原生格式化函数处理。

显示数量时，按数值的类型选择函数：

- 需要分组显示的整数用 `theme::counted`。
- 小数数量用 `theme::quantity`。

两个函数都把原始数值交给 `i18n::format_count` 选择复数形式，再用区域格式化的结果替换 `{count}`，避免把分组符当作小数点。刷新间隔等小数也通过区域格式化函数显示。

组件库 `gpui-component` 另有自己的文案目录，仅含英文、简体中文、繁体中文和意大利文。这份目录用于组件库自行绘制的文字，即触摸长按文本框时的编辑菜单和无障碍标签。

`catalog::set_locale` 在设置界面语言时，把同一语言标签传给组件库，组件库目录中没有的语言回退到英文。文本框的右键菜单由 `widgets::input` 用 `common.edit` 的文案构建，覆盖全部语言。

使用带内置文字的组件时，同样从 `locales` 传入文案。

## 检查文案

文案的改动用 `pnpm i18n` 检查，排版用测试窗口的截图复核。

### 运行自动检查

`pnpm i18n`（`node scripts/i18n.mjs`）检查以下内容：

- 文案键与占位符
- 各语言所需的复数形式
- 富文本嵌套
- 空译文与隐藏控制字符
- 月份数量
- 原生层、桌面和安装程序的语言注册是否与 `locales/` 的目录一致
- 应用和官网的固定术语与单位

汉字与语言名称按以下规则检查：

- **汉字**：语言标签以 `zh` 或 `ja` 开头的译文（繁体中文与日文）可含汉字；其他语言的译文含 U+3400–U+9FFF 或 U+F900–U+FAFF 的字符时，按未翻译的中文报错。
- **语言名称**：`common.json` 中 `languageName` 下的各项不做汉字检查，各语言都须与源文案相同，即使用每种语言的原生文字。

编写测试时，使用显式的语言参数，避免修改进程级的语言或断言具体的译文。

### 复核窗口排版

复核窗口时运行以下命令，以日语为例；更换标签和语言后，可复用同一个步骤文件：

```powershell
node scripts/ui-shots.mjs l10n-ja tools/window-probe/steps/localization.json --language ja-JP
```

`localization.json` 覆盖所有页面、首次启动引导、最小窗口与 20 px 字号、150% 界面缩放。

安装向导的文字需同时考虑 NSIS 控件的高度和各语言字体的实际行高。

## 增加语言

增加一种语言时，按以下步骤修改，其中 `<标签>` 是该语言的标签，格式与已有目录相同，如 `fr-FR`：

1. 在 `locales/<标签>/` 下按 `zh-CN` 补齐全部命名空间的译文，包括 `installer.json` 中安装程序的字体 `ArgusFace` 和 `format.json` 中 12 个月份的 `monthNames`。
2. 在每种语言的 `common.json` 中加入 `languageName.<去掉连字符的标签>`，值都写该语言的原生名称。**设置 → 语言与外观 → 界面语言**与首次启动引导按 `Locale::ALL` 列出语言，选项显示的就是这个名称。
3. 在 `resources/changelog.json` 中登记语言名称、更新日志的标题与各类小节标题。新建 `changelog/<标签>.md`，与简体中文版逐条对应地补齐译文，并在各语言更新日志顶部的语言列表中加入该语言。
4. 在 `crates/argus-core/src/i18n.rs` 中为 `Locale` 加入成员及其 `serde(rename)` 标签，补齐 `ALL`、`tag` 与嵌入 `native.json` 的 `catalog`。同一文件中，在 `from_langid` 中按 Windows LANGID 的主语言识别该语言，在 `plural` 中加入 CLDR 基数规则。
5. 在 `crates/argus-view-logic/src/catalog.rs` 中用 `register!` 注册桌面文案目录。
6. 在 `src-gpui/src/frontend/release_notes.rs` 的 `source` 中嵌入该语言的更新日志，在 `src-gpui/src/commands.rs` 的 `website_page` 中指定打开官网时的语言目录。官网的语言在 `website/src/lib/languages.ts` 中另行维护。
7. 在 `scripts/lib/installer-locales.mjs` 的 `installerLanguages` 中把标签对应到大写的 NSIS 语言名，如 `RUSSIAN`。再在 `packaging/windows/installer-template.nsi` 中用 `!insertmacro MUI_LANGUAGE` 加入同一语言。
8. 在 `.github/ISSUE_TEMPLATE/translation.yml` 的语言列表中加入该语言。
9. 运行 `pnpm i18n`，再用模拟快照检查所有页面的排版，见[复核窗口排版](#复核窗口排版)。

`pnpm i18n` 核对各语言的目录是否齐全、语言名称是否一致，以及第 4、5、7 步的注册是否与 `locales/` 的目录一致。为 `Locale` 加入成员后，编译器会指出 `tag`、`catalog`、`source` 与 `website_page` 中缺少的分支。

`ALL`、`from_langid` 与 `plural` 缺少该语言时仍能编译，需自行补上。安装程序把所选语言的 LANGID 传给安装帮助进程，`from_langid` 不认识这个 LANGID 时，复制主程序一步失败，安装无法完成。

以下两处按语言的特点修改：

- 该语言的 `one` 只用于数值 1 时（如英文、德文、西班牙文），在 `scripts/lib/locale-validation.mjs` 的 `maySpellOne` 中加入该语言，`one` 形式的译文即可不写 `{count}`。
- 该语言需要专用的汉字字体回退时（如日文、繁体中文），在 `resources/theme.json` 的 `fonts` 中加入回退列表，并在 `src-gpui/src/frontend/theme.rs` 的 `fallbacks` 中选用。

## 界面语言

系统语言按以下顺序确定：

1. 使用 Windows 显示语言。
2. 显示语言不受支持时，查找用户的首选语言列表。
3. 仍未找到时，使用英文。

同一语言的区域变体共用目录，如 `es-MX` 使用 `es-ES`、`fr-CA` 使用 `fr-FR`。中文按脚本区分，显式的脚本优先于地区：

| 语言标签 | 使用的目录 |
| --- | --- |
| 脚本为 `Hant` | `zh-TW` |
| 脚本为 `Hans` | `zh-CN` |
| 未指定脚本，地区为中国台湾、中国香港、中国澳门 | `zh-TW` |
| 未指定脚本，其他地区 | `zh-CN` |
| 旧式的 `zh-CHT`、`zh-CHS` | 分别为 `zh-TW`、`zh-CN` |

辅助进程可通过 `ARGUS_LOCALE` 继承语言，服务使用所在系统账户的显示语言。

切换语言时，重新构建表头、菜单及主题标签。字体回退按语言分别缓存：日语优先使用 Yu Gothic UI / Meiryo，韩语优先使用 Malgun Gothic，繁体中文优先使用 Microsoft JhengHei UI / Microsoft JhengHei。

## 复数

复数形式按原始数值参数 `count` 和 CLDR 基数规则选择，原生层和界面共用选择逻辑。各语言使用的形式如下：

| 语言 | 复数形式 |
| --- | --- |
| 中文、日文、韩文 | `other` |
| 英文、德文 | `one`、`other` |
| 西班牙文、法文 | `one`、`many`、`other` |
| 俄文 | `one`、`few`、`many`、`other` |

`many` 覆盖法文和西班牙文的整数百万倍数。俄文区分 1、2–4、5–20 及 21、22 等尾数，有小数部分时使用 `other`。

法文和俄文的 `one` 覆盖多个数值，译文必须保留 `{count}`。

选择复数形式时，先在同一语言中依次查找该数值对应的形式、`other` 和不分形式的文字，再按[键名](#键名)中的顺序查找英文与源文案。

## 区域格式

数字与完整日期遵循 Windows 区域设置，独立于界面语言。版本、PID、端口、路径、设置文件和协议数据保持原格式。

### 数字与日期

各项的格式如下：

- **数字**：小数点、分组符及分组位数在启动时读取。
- **日期**：使用系统的短日期和时间格式。
- **时间戳**：按该时刻的本地时区偏移转换。

区域格式测试直接对照 Windows 的区域 API，时区测试读取 Windows 时区数据库，均不改变系统设置。

### 历史曲线的时间

历史曲线的紧凑日期标签使用界面语言，时间轴保持 24 小时制。

刻度按本地时间边界计算，跨夏令时跳过不存在的时刻，并保留回拨后重复的时刻。选中的时刻附加 UTC 偏移，标签宽度使用实际字体测量。

### 输入

数字输入保留输入法组字，提交时识别区域小数符、点号及全角数字，不解析分组符。

快捷键录制从主窗口当前的原生消息获取虚拟键与修饰键；松开修饰键或字形变化后，仍以同一虚拟键结束录制。测试输入保留字符映射回退。

## 术语表

术语表规定固定缩写、标识与单位的写法，并列出常用界面术语在各语言中的译名。

### 固定缩写、标识和单位

应用、官网及其界面演示共用以下规则，README 与更新日志沿用同一写法。机器可读清单位于 [`resources/terminology.json`](../../resources/terminology.json)，由 [`terminology.mjs`](../../scripts/lib/terminology.mjs) 检查，并接入 `pnpm i18n` 和官网文案测试。

| 类别 | 固定写法 |
| --- | --- |
| 核心指标 | `CPU`、`GPU`、`I/O`、`PID` |
| 协议与接口 | `SMART`、`NVMe`、`ATA`、`SATA`、`SCSI`、`USB`、`PCIe`、`TCP`、`UDP`、`IPv4`、`IPv6` 等 |
| 硬件与传感器 | `CPUID`、`MSR`、`RAPL`、`NVML`、`IGCL`、`VID`、`PPT`、`TDC`、`EDC`、`FCLK`、`MCLK`、`UCLK` 等 |
| 技术名称与代码 | `PawnIO`、`DirectX`、`EcoQoS` 等，以及路径、文件名、命令行参数和注册表项 |
| 容量与速率 | `B`、`KB`、`MB`、`GB`、`TB` 及对应的 `/s` |
| 网络比特速率 | `b/s`、`Kbps`、`Mbps`、`Gbps`、`Tbps` |
| 二进制前缀 | `KiB`、`MiB`、`GiB`、`TiB` |
| 频率与硬件读数 | `Hz`、`kHz`、`MHz`、`GHz`、`W`、`mW`、`V`、`mV`、`A`、`mA`、`°C`、`RPM`、`MT/s` |

各类写法的规则如下：

- 核心指标在九种语言的资源标签、列名、分组和指标中统一使用，周围的文字按语言翻译，如 `Чтение (I/O)`、`Lecture I/O`、`I/O lesen`。
- 协议与接口保留标识及大小写。
- 硬件与传感器保留标识，描述性文字使用各语言的译名。
- 技术名称保留原文，路径、文件名、命令行参数和注册表项保留准确的拼写。
- 容量与速率沿用格式化器的写法，换算基数由数据与格式化器确定。明确使用二进制前缀的文字保留 `KiB`、`MiB`、`GiB`、`TiB`。
- 频率与硬件读数保留上表的单位，如俄语的电压标签写作 `+3,3 V`，内存读数使用 `GB`。

数字格式、数值与单位之间的空格、百分号的间距遵循现有的区域与语言规则。“秒”“像素”“帧/秒”等自然语言表达继续本地化。单位符号的大小写和前缀保留原义，例如 `MB/s`、`Mbps`、`MiB` 分别表示不同的单位。

固定缩写的检查覆盖源文案中的对应术语，`exactLabels` 另行固定资源名等独立标签。调整键名时同步更新清单，检查会报告失效的键。

完整自然译法的例外按文案键记录在 `localizedPhrases`。例如 CPU 时间可写作法语 `Temps processeur`、俄语 `Время процессора`，I/O 的说明句可使用完整的输入输出译名。例外仍遵循统一缩写规则，使用缩写时写作 `CPU`、`GPU`、`I/O`。新增例外应写明具体语境，并补充回归用例。
