# 统计口径

本页说明部分读数的统计口径：内存、GPU、进程磁盘读写与电源使用情况如何计算，以及网络速率的单位。界面中的用法见[进程页](processes.md)与[性能页](performance.md)。

## 内存统计口径

概况带、进程表头与进程行的**内存**采用不同的口径。在概况带的内存数值、进程表头的**内存**和分类标题的内存合计上悬停，可看到对应口径的说明：

| 位置 | 统计含义 |
| --- | --- |
| 概况带的已用内存 | 整机总物理内存减去可用内存，包含使用中与已修改的部分 |
| 进程表头的内存百分比 | 上述整机占用占总物理内存的比例 |
| 进程行、应用组及分类标题的内存数值 | 专用工作集，即进程独占且驻留在物理内存中的部分；组与分类按该口径合计 |

分类标题合计各进程的专用工作集，例如 **Windows 进程**统计该分类内进程的专用工作集。整机占用还涉及共享驻留页、内核与驱动、页表、使用中的系统缓存和已修改页等。

完整工作集包含共享页，直接累加会重复计算进程间共享的部分。

备用内存计入“可用”。查看系统各类内存的占用，应使用**性能 → 内存**中的组成数据，见[内存](performance.md#内存)。各类内存的采集来源见[硬件数据](hardware-data.md)。

## GPU 统计口径

进程的 GPU 占用取最忙的单个引擎。应用组及分类标题先按适配器、物理 GPU 和引擎节点的完整身份汇总进程的贡献，再取最忙的节点。不同显卡或引擎节点分别计算，同名引擎按各自的节点区分。

集成显卡使用的系统内存计入共享 GPU 内存，仅固件预留给显卡的部分计入专用 GPU 内存。共享资源可归属于多个进程，整张显卡的物理用量见[性能页](performance.md#gpu)。

整体占用以 Windows 引擎计时为基础，不低于有效的进程引擎读数；NVIDIA 显卡另用 NVML 核心利用率补充计算负载。NVML 补充不改写原生引擎曲线。性能页显示本次的来源，概况带的 GPU 数字也可悬停查看来源。

与其他工具比较时，须同时核对适配器、引擎和采样窗口，分别对照视频、3D 与计算负载的对应指标。

## 磁盘读写计数的归属

进程的**磁盘读取**和**磁盘写入**取自 Windows 为每个进程累计的磁盘字节数，与磁盘实际的读写存在以下差异：

- 由文件缓存直接提供的读取不计入。
- 经缓存的写入在程序写入时即计入，由系统稍后写到磁盘，因此进程的写入速率可在短时间内高于磁盘的实际速率。
- Windows 记录的读取字节数可能集中在一次采样内增加，大量读取的进程可在个别采样中显示超过磁盘性能上限的速率。采样间隔越短越明显，启动后最初几次采样的间隔可短至约 0.3 秒。

这组计数按发起读写的进程归属：

- 经缓存写入的数据由系统写到磁盘时，不再计入其他进程。写入后很快删除的临时文件、在缓存中被反复覆盖的数据，会使程序的累计写入高于实际写到磁盘的量。
- 缓存未命中时，系统为顺序读取所做的预读计入发起读取的程序。
- 通过内存映射写入的数据在刷新时，计入调用刷新的程序。
- 文件系统元数据与日志（如 NTFS 日志、MFT、USN 变更日志）等不由程序直接发起的磁盘读写计入 System 进程，因此 System 的磁盘写入请求数可远多于它自身的写入操作数。系统长时间运行、文件频繁变化时，它的累计读写可达数百 GB。

Windows 搜索索引器（`SearchIndexer.exe`）在索引位置内的文件频繁变化时，持续读写自己的索引数据库，累计量同样可观。可在**索引选项**中排除频繁写入、无需搜索的文件夹。

## 电源使用情况的估算方法

**电源使用情况**与**电源使用情况趋势**两列按进程的 CPU、GPU 与磁盘活动估算耗电水平。Windows 未公开这两列的计算方法，Argus 自行估算，权重与分级见[电源使用情况](../architecture/core/process.md#电源使用情况)中的 `power.rs`。

估算的等级表示相对水平，不是实际功耗，可能与系统任务管理器的显示不同。

## 网络速率的单位

网络速率默认以字节每秒显示（KB/s、MB/s），与磁盘一致；可在**设置 → 数据与历史**中改为比特每秒（Kbps、Mbps），与网卡的链路速度、宽带套餐一致。概况带、进程表、详细信息面板和历史页随之切换，性能页的网络视图总是同时显示两种。
