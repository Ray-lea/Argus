# 设置

设置页按分组排列，左侧的分组列表跟随滚动标出当前位置，单击可以直接跳到对应分组；窗口较窄时只显示设置本身。

## 语言与外观

界面支持简体中文与英文，默认“跟随系统”：Windows 的显示语言为中文（任一地区）时使用简体中文，其他语言使用英文。切换后立即生效，托盘菜单、窗口标题和错误提示也随之切换。

特权服务以 SYSTEM 身份运行，管理员授权后运行的维护助手也在独立的进程中，它们使用 Windows 的显示语言；当 Argus 的语言与 Windows 显示语言不同时，来自这些进程的少量提示会以 Windows 的语言显示。安装程序和卸载程序同样按 Windows 的显示语言显示中文或英文。

“主题”可选“跟随系统”“浅色”或“深色”，默认跟随系统：使用 Windows“个性化 → 颜色”中的应用模式，系统切换时随之切换。选择浅色或深色后，窗口内容、标题栏与背景都固定为该主题，不再跟随系统。托盘菜单、系统对话框以及安装和卸载程序仍跟随 Windows。

“导航栏位置”可选“顶部”（默认）或“侧边”。顶部导航栏以标签形式排列在工具栏下方，切换页面时新页面从左右方向滑入；侧边导航栏位于窗口左侧，默认仅显示图标，可通过左上角的 ☰ 按钮展开显示页面名称。首次启动引导中也可选择，设置保存在本机，重启后保留。

## 启动与后台

| 设置 | 说明 |
|---|---|
| 登录 Windows 时启动 | 在托盘中静默启动（`--hidden`），需要时用快捷键或单击托盘图标打开。在由任务管理器替换打开的窗口中开启时，启动项同样指向已安装的 Argus；未找到安装版时提示退出后直接运行 Argus 再开启。旧版本在这种窗口中开启时，启动项指向替换所用的界面副本，运行一次已安装的 Argus（例如从开始菜单）即改回已安装的程序。 |
| 关闭窗口时保留在托盘 | 默认开启。窗口隐藏时按“后台常驻时的刷新间隔”（默认 5 秒）采样，历史记录和规则照常进行。关闭这一项后，关闭窗口即退出 Argus。 |

## 快捷键

显示或隐藏 Argus 的全局快捷键，默认 Ctrl+Alt+Esc，在大多数程序中都能使用。

- 右侧的开关可停用快捷键，停用时保留当前组合，重新开启即恢复。
- 单击“更改”后，卡片下方显示录制区：按下组合键再松开即可保存，保存的同时开启快捷键。录制时按住的键实时显示，左右修饰键分开显示；按 Esc 或单击“取消”放弃，按 Backspace 停用快捷键。当前组合不是默认值时，录制区还有“恢复默认”，可改回 Ctrl+Alt+Esc。切换到其他窗口、隐藏窗口或 15 秒内没有按键时，录制自动结束，原快捷键不变。
- 组合已被其他程序占用时，卡片下方显示原因和“重试”按钮；占用的程序退出后，再次显示 Argus 窗口时也会自动重试。
- 组合须包含 Ctrl、Alt 或 Win 之一和一个普通键；F13–F24 可以单独使用，Shift+F1–F9 和 Shift+F11 需确认后才保存。这是 Windows 全局快捷键的规则：修饰键不区分左右（左 Ctrl 与右 Ctrl 等效）；仅由修饰键组成的组合（如左 Ctrl+右 Ctrl+左 Alt）不能使用；只能有一个普通键，两个普通键（如小键盘的 + 和 -）不能组合；须先按住修饰键，再按普通键。
- CapsLock、NumLock 和 ScrollLock 不参与组合；按住或开启 CapsLock 不影响快捷键触发。
- 不能使用的组合：只含 Shift 的组合（会影响所有程序中的正常输入）、Ctrl+C、Ctrl+V 等编辑操作、Alt+F4、Alt+Tab、Alt+Space、Ctrl+Esc、F12 等系统与通用操作，以及 Ctrl+Shift+Esc（可在“权限”中让 Argus 替换系统任务管理器）。带 Ctrl 的 Pause 组合同样不能使用（按住 Ctrl 时 Pause 键发出的是 Break）。只含 Ctrl 或 Alt 的普通组合、Argus 自身的 Ctrl+1–7 与 Ctrl+F、Ctrl+空格、小键盘的数字和小数点键以及 PrintScreen 组合需确认后才保存。
- 字母键按当前键盘布局键帽上的字母录制。用 AltGr（右 Alt，或与之等效的 Ctrl+Alt）输入字符的布局（德语、法语等）中，输入字符的组合不能用作快捷键，录制时设置页会提示换一个键或修饰键。

背后的实测与取舍见[全局快捷键](../design/hotkey.md)。

## 权限

“特权服务”默认未安装。单击“安装并启用”，确认授权范围后完成 Windows 的管理员授权，Argus 的界面继续以标准权限运行，以下功能会使用后台服务：

- 结束进程或进程树（仍拦截系统关键进程）。
- 设置进程优先级、开启或关闭效率模式。
- 自动规则中的优先级与效率模式操作。
- 每进程网络流量采集（本地采集不可用时）。
- 每进程磁盘读写采集（系统未通过普通进程查询提供计数时）。
- 按句柄查文件及目录占用（包括进程当前目录）。
- 启动、停止、重启 Windows 服务，以及修改启动类型。
- 断开 IPv4 TCP 连接。

这一授权属于当前 Windows 账户，而不是 Argus 程序本身：此账户下以标准权限运行的任何程序都能调用服务的管理功能，无需再次授权。这些功能的作用范围是整台电脑，包括结束任意用户的进程（系统关键进程除外）、启动或停止任意 Windows 服务并修改启动类型（安全软件与 Windows 更新相关的服务也不例外）、断开任意 IPv4 TCP 连接，以及查询所有进程的文件占用、网络流量与磁盘读写。安装特权服务相当于让该账户获得了部分管理员权限，请只在自己使用的账户上安装。在受限环境（受限令牌或 AppContainer 沙盒）中运行的程序不能调用服务。

服务随 Windows 启动，一次安装只授权一个账户；另一个账户需先经管理员授权卸载，再安装。

“权限”分组中每项功能各占一张卡片：上方是功能说明，右侧以彩色圆点标出当前状态（绿色为正常，橙色需要处理，灰色为未启用）；下方是状态说明、错误提示和操作按钮。特权服务的状态为未安装、已连接、版本不兼容、已停止或错误。服务停止后可“启动服务”；更新 Argus 后可“更新服务”，将新版程序复制到受保护的服务目录。服务版本与 Argus 不一致时卡片中会提示。升级 Argus 时安装程序会一并更新服务；启用了任务管理器替换或服务未能更新时，Argus 升级后首次启动会询问是否更新服务。服务版本过旧、与 Argus 不兼容时，卡片显示“正在运行，版本不兼容”，单击“更新服务”后即可连接；在此之前状态栏显示“标准权限”，结束进程、设置优先级与效率模式、控制服务、断开连接和规则都按 Argus 自身的权限执行，权限不足时提示特权服务版本不兼容，提示条上的“更新服务”可转到此处的特权服务卡片；每进程网络流量等由服务提供的数据在更新前不显示。启用了任务管理器替换时，单击“更新服务”会先确认：更新会先恢复 Windows 任务管理器。取消管理员授权会保留现状。连接中断或操作超时时不会自动重复执行，请刷新对应页面确认结果。

“卸载”会停止并移除服务，Argus 继续运行，操作恢复为当前进程的权限。从“设置 → 应用”卸载 Argus 时，卸载程序检测到特权服务会询问是否一并卸载（需要管理员授权）；选择保留时服务继续随 Windows 启动。使用免安装版时，删除程序前应先在这里卸载服务。后台程序是独立副本，移动免安装版不会中断已经安装的服务。

**免安装版的风险**：安装或更新特权服务、启用任务管理器替换、安装或启动 PawnIO 时，Argus 会以管理员身份运行自身；安装特权服务还会把自身复制为以 SYSTEM 身份运行的服务程序。安装版位于 Program Files，只有管理员能修改；免安装版则可以放在任意位置，如果它所在的文件夹允许标准用户写入（例如“下载”文件夹或桌面），本机已有的恶意程序就可能在这之前替换 `argus.exe`，借用户的管理员授权获得 SYSTEM 权限。需要特权服务时建议使用安装版；使用免安装版时，请把它放在只有管理员能写入的文件夹中。

详细信息、启动项修改，以及文件占用查询中的 Restart Manager 部分仍使用 Argus 本身的权限。句柄查询可使用服务；服务不可用时以当前账户权限降级查询。服务已连接时，状态栏右下角的权限标记显示“特权服务”（界面进程本身仍以标准权限运行），服务停止或断开后约半分钟内恢复为“标准权限”；受保护的系统进程可能拒绝特权服务的操作。

网络流量会在后台异步读取，通常比本地采样晚一个刷新周期；服务断线或采集不可用时隐藏网络列，恢复后先建立计数基线，避免把积累的字节显示成瞬时峰值。没有客户端读取 15 秒后，服务会关闭 ETW 会话；再次读取时重新启动。

## 内核传感器

首次启动引导在“特权服务”之后提供可选的“内核传感器”步骤。未连接服务时可单击“配置特权服务”返回对应步骤；服务就绪后，单击“启用内核传感器”即使用下述自动安装与启动流程。单击“下一步”可跳过本项，不触发驱动操作。进度与设置页共享，取消或失败时显示原因并可重试。已完成引导的安装不会重复弹出，可在“设置 → 关于”重新打开。

“权限”分组提供“内核传感器”开关，默认关闭。先安装或更新并启动 Argus 特权服务，再开启开关。Argus 自动检查 PawnIO：缺少或版本低于 2.2.0 时下载并安装官方版本，已安装且符合要求时启动驱动，已经运行的较新版本直接复用。安装或启动需要管理员授权，界面本身保持原有权限。

官方 2.0 旧版使用不同的安装方式：Argus 识别已知的官方签名驱动文件，确认默认安装位置与卸载信息后，先校验新旧安装包，再通过旧版官方卸载程序移除旧版、安装新版。升级前应退出使用 PawnIO 的其他硬件监控程序；旧服务未移除或安装程序要求重启时，重启 Windows 后再次开启。安装信息不一致时停止自动迁移，可通过 Windows 的应用管理卸载旧版，再从 PawnIO 官网安装新版。

处理期间显示状态并禁用重复操作，切换页面不会丢失进度。取消授权、下载或签名校验失败、驱动受系统策略阻止时，开关保持关闭并显示原因；安装程序报告需要重启时，重启 Windows 后再次开启。仅手动开启触发安装或管理员授权，恢复已保存的设置不会自动弹出授权框。“PawnIO 官网”保留手动安装入口。安装包固定为官方版本及 SHA-256，并校验 Windows 签名；不启用测试签名或修改内存完整性等系统安全设置。

PawnIO 设备在 Windows 中被禁用时，须先在设备管理器启用后重试；设备配置标记为待重启时，须先重启。服务列表显示“正在运行”并不代表设备已可用，Argus 会同时核对设备状态，检查未通过时不保存开启状态。

性能页的 CPU 视图在“内部传感器”卡片中按功耗、电压、频率、温度分组显示读数，在“每核读数”卡片中提供每个物理核心的温度、有效频率、功耗、VID 与活跃比例。Ryzen 7000/9000 的 SVI3 供电电压与 VID 分开标注；Intel 提供 PL1／PL2、温度余量、Ring 频率与限制状态；当前状态与硬件历史记录分开显示。Windows 空闲状态与 AMD SMU 驻留比例分别标注。支持的主板还显示风扇通道转速，以及已匹配的电源轨、主板与供电温度。支持的硬件范围见[硬件数据](hardware-data.md#消费级硬件兼容范围)。

关闭开关后停止请求内核读数，Windows 自带采集继续工作；服务在 15 秒无读取后释放模块。关闭开关或卸载 Argus 不卸载共享的 PawnIO 驱动，可通过 Windows 的应用管理单独卸载。

## 替换系统任务管理器

“权限”分组的“替换系统任务管理器”卡片显示系统任务管理器替换的状态，首次启动引导中也可直接开启。功能默认关闭，发布版在安装特权服务并授权给当前账户后才提供“启用替换”。它影响整台电脑上 taskmgr.exe 的启动入口，包括 Ctrl+Shift+Esc；授权账户打开 Argus，其他账户仍尝试打开 Windows 任务管理器。已有其他替换或路径过滤配置时拒绝开启，不自动覆盖；卡片显示“已有其他配置”，并写明 taskmgr.exe 的 IFEO 键中发现了什么：与当前 Argus 配置不一致的 Debugger 值、UseFilter 值，或 `PerfOptions` 之类的子项。值不一致不能证明使用过其他任务管理器，需核对卡片所显示的配置来源，通过对应程序恢复后，再单击“刷新状态”。

开启需要管理员授权，并先完成启动器运行、调试脱离与界面就绪检查。自检不为临时程序写入任务管理器替换配置；通过检查后，才保存恢复记录并修改 taskmgr.exe 的配置。Argus 无响应时，独立启动器尝试打开原生任务管理器。该路径仍可能受系统策略、权限或文件损坏限制。

若提示注册表权限检查通过但操作仍被拒绝，可检查 360 等安全软件的注册表或系统防护记录，核对被拦截的操作及程序是否为 Argus 的任务管理器替换，然后允许本次修改并重试。仅安装了安全软件不能证明是其拦截，需有对应记录；没有记录时可提供 Argus 的诊断日志，其中包含失败 API 与错误码。Argus 不自动添加安全软件信任规则、不关闭防护或强制改写注册表权限。持续误报可通过 [360 软件开放平台](https://open.soft.360.cn/guide/guide_1.php?i=3)申诉，提交与被拦截文件一致的版本。

“恢复 Windows 任务管理器”优先通过特权服务还原，服务不可用时请求管理员授权。界面无法运行时，使用卡片底部给出的路径中的 `argus-taskmgr-recover.exe`；它不依赖 WebView2 或后台服务。独立恢复程序也损坏时，参照其同目录的 `taskmgr-recovery.txt`，核对归属后只还原 Debugger 值，不删除整个键。

卸载特权服务会先关闭替换，单击“卸载”时的确认框中会说明。更新特权服务时替换保持开启，替换所用的界面和启动器随之更新到新版本；通过安装程序升级 Argus 时同样如此。免安装版直接替换程序文件，或安装程序未能完成更新时（例如当时启动器正在运行），按 Ctrl+Shift+Esc 打开的仍是旧版本，卡片中会写明其版本号，在特权服务中单击“更新服务”即改为打开当前版本。升级时由替换打开的旧版 Argus 仍在运行（例如常驻托盘）的，此后打开 Argus 显示的仍是它，从托盘退出后才是新版本，因此升级前宜先退出它。替换已恢复后，其他工具写入的任务管理器替换不影响更新或卸载服务。卸载 Argus 前也必须通过恢复检查；升级安装时选择“先卸载再安装”不做这项检查，替换保持原样。冲突或恢复失败会保留文件并阻止相关卸载。详细过程见[系统任务管理器替换](../architecture/task-manager.md)。

## 数据与历史

| 设置 | 说明 |
|---|---|
| 刷新频率 | 每 0.5、1（默认）、2 或 5 秒采样一次。间隔越短曲线越细腻，Argus 自身的开销也越高。工具栏上也可以切换刷新频率或暂停刷新；暂停时界面不再更新，历史记录和规则照常进行（每 5 秒采样一次）。 |
| 最小化时的刷新间隔 | 窗口最小化后的采样间隔：每 0.5、1、2、5（默认）、10 或 30 秒。窗口最小化时 WebView 停止绘制，只保留采样。间隔越长后台开销越低，但规则对新启动程序的生效最多延后一个间隔；长于 5 秒时，历史记录也随之变稀。 |
| 后台常驻时的刷新间隔 | 隐藏到托盘（包括开机启动后未打开窗口）时的采样间隔，选项与默认值同上，托盘的悬停提示按此间隔更新。 |
| 网络速率单位 | 字节每秒（MB/s，默认，与磁盘一致）或比特每秒（Mbps，与网卡的链路速度、宽带套餐一致），整个应用统一切换。性能页的网络视图总是同时显示两种。 |
| 记录历史 | 默认开启。每 5 秒记录一次资源占用和当时最忙的进程；最小化或后台常驻时的刷新间隔长于 5 秒时，按该间隔记录。只保存在本机，保留 7 天，在[历史页](README.md#历史)查看。关闭后不再记录新的数据，已有的记录照常在 7 天后过期。 |
| 已保存的历史 | 显示历史记录占用的空间和最早的一条记录；“清除”会在确认后删除全部历史记录。 |

两项后台刷新间隔改为短于 5 秒时，先弹出确认：说明 Argus 将以该间隔在后台采样全部进程与硬件数据，CPU 占用与耗电随之增加，使用电池时更为明显。取消则保持原来的间隔。首次启动引导的“常驻后台”一步也提供这两项，规则相同。

窗口从最小化或托盘回到前台时，如果这段时间的刷新间隔比前台的“刷新频率”长，右下角会提示一次刷新间隔的变化，例如“最小化期间，刷新间隔由 1 秒放宽至 5 秒”。提示中的“调整间隔”打开本页并定位到对应的设置项；“不再提醒”只关闭这一种提示，最小化与后台常驻的提示分别设置。窗口只离开片刻、还不到一个前台刷新周期时不提示；回到前台时正显示首次启动引导、更新对话框或确认框，或是更新后首次显示窗口（此时显示新版本的更新内容）时，这一次也不提示。

## 规则

程序启动时自动设置优先级或效率模式。在分组顶部输入程序名（例如 `chrome.exe`）并单击“添加”即可新建规则。每条规则包括：

- **程序名**：不区分大小写；同名的多个进程都会套用。程序正在运行时，规则前面显示它的图标。
- **优先级**：不改变，或实时、高、高于正常、正常、低于正常、低之一。
- **效率模式**：不改变、开启或关闭。
- **启用开关**：停用后保留规则但不再套用。

规则保存后会立即排入后台应用队列，作用于已在运行的进程，此后每当该程序启动就再套用一次；窗口隐藏在托盘时也照常生效。规则通信不会阻塞刷新，慢请求期间只保留最新的进程列表。

每条规则下方显示已应用、权限不足和执行失败的进程数；保存规则或权限来源改变时重新计数。安装、停止或重启特权服务后，已有进程会重新检查。请求发出后丢失回复时不自动重复操作，可检查服务状态后重新保存规则来重试。

也可以在进程列表中右键一个进程，选择“添加规则”：Argus 会以它当前的优先级和效率模式建好规则，并转到这里。

## 更新

Argus 从 GitHub Releases 获取新版本。发现新版本后在后台下载，下载完成并通过签名校验后：

- 标题栏右侧、窗口按钮左边显示一个强调色的圆形更新按钮，各页面均可见，指针悬停时显示新版本号。右键单击该按钮可选择“此版本不再提醒”，之后仅在导航栏的“设置”和设置页的“更新”分组上显示提示点。
- 窗口处于显示状态时，右下角提示一次“Argus x.y.z 已准备就绪”；窗口隐藏在托盘时，在下次显示窗口时提示；首次启动引导打开时，在引导结束后提示。每个版本仅提示一次，启动时不弹出对话框。
- 托盘图标右下角显示强调色圆点，悬停提示增加“新版本 x.y.z 已就绪”，托盘菜单增加“更新到 x.y.z…”。

单击更新按钮、托盘菜单项或“更新”分组中的“查看更新内容”，打开更新对话框；首次启动引导打开时，对话框在引导结束后打开。对话框显示当前版本与新版本、新版本的通道和发布日期、安装包大小与签名校验结果，以及当前版本之后每个版本的更新内容：按新功能、修复、性能等分类，最新版本默认展开，跳过的版本可单击展开。单击“重启并更新”开始安装，需要管理员授权：安装期间 Argus 将退出，安装程序仅显示进度条，完成后自动以标准权限重新启动 Argus 并回到原来的页面；从托盘隐藏状态开始的更新，重新启动后仍保留在托盘。取消管理员授权时不安装，更新仍可稍后安装。

更新完成后首次打开窗口时，显示新版本的更新内容：更新前后的版本号，以及其间每个版本的变化。关闭对话框后不再出现，直到下次更新；无论通过应用内更新还是手动运行安装程序，都按版本号判断。窗口隐藏在托盘时等到显示窗口、首次启动引导打开时等到引导结束后再显示；由任务管理器替换启动时不显示，留到下次打开。关闭“更新后显示更新内容”后，改为在右下角提示“Argus 已更新到 x.y.z”，单击“查看更新内容”可阅读。单击“查看本版本更新”或“关于”中的“更新内容”，可随时查看当前版本的更新内容。

已下载的安装包保存在 `%LOCALAPPDATA%\dev.argus.taskmanager\updates`，退出 Argus 后无需重新下载：再次启动时重新校验签名，通过后直接显示为可安装；安装前再校验一次，安装包被修改或删除时重新下载。安装完成后自动删除。

| 设置 | 说明 |
|---|---|
| 自动检查更新 | 默认开启。启动约 1 分钟后检查一次，此后每天检查一次；检查失败时 6 小时后重试。关闭后仅在单击“检查更新”时检查。 |
| 更新后显示更新内容 | 默认开启。更新完成后首次打开窗口时显示新版本的更新内容，每个版本仅显示一次；关闭后改为右下角的提示。同一行的“查看本版本更新”可随时打开当前版本的更新内容。 |
| 更新通道 | 稳定版（默认）仅接收正式版本；测试版同时接收预发布版本（如 `1.2.0-beta.1`），提前提供新功能，稳定性可能不及稳定版。由测试版切换到稳定版后，需等到稳定版的版本号高于当前版本时才会更新，不会降级。 |
| 下载线路 | 自动（默认，优先连接 GitHub，失败时依次使用加速代理）、仅连接 GitHub、仅使用加速代理。 |
| 加速代理 | 内置 gh-proxy.com、gh-proxy.org、ghfast.top，也可填写自定义代理，即添加在 GitHub 地址之前的前缀，须使用 https。 |

加速代理由第三方提供，可获知本机的 IP 地址及所下载的文件。安装包带有发布者的签名，签名同时覆盖版本号；Argus 仅安装签名正确、版本号与签名一致且高于当前版本的安装包，因此代理无法篡改更新，也无法以旧版本冒充新版本，至多导致暂时无法获取更新。更新内容同样带有发布者的签名并绑定版本号，未通过校验的更新内容不显示。

免安装版（`Argus_<版本>_x64.exe`）不支持自动更新：发现新版本时同样显示更新按钮和更新内容，单击“前往下载”打开发布页。开发版不检查更新。

已安装特权服务时，安装程序在同一次管理员授权中一并更新服务；启用了任务管理器替换时，替换保持开启，所用的界面和启动器也随之更新到新版本。安装程序未能更新服务时，更新后首次启动时询问是否更新服务，见[权限](#权限)。

## 关于

诊断日志记录实际运行程序的 SHA-256，可区分版本号相同的不同测试构建；由任务管理器替换启动时，摘要对应正在运行的替换副本。“特权服务版本相同”仅指发布版本号相同。日志不记录程序所在路径。

显示版本号、当前权限（管理员、标准权限，或标准权限且特权服务已连接）和版权声明，并提供“更新内容”（当前版本的更新内容）和“退出 Argus”。“首次启动引导”可以重新打开第一次启动时的引导。“交流与反馈”显示反馈交流 QQ 群的群号（453803497）：单击“加入 QQ 群”在浏览器中打开加群页面，由 QQ 完成加群；单击“复制群号”复制群号。“许可证”一项说明 Argus 以 GNU Affero General Public License 第 3 版或更高版本发布、不提供任何担保，单击“查看许可证”可以阅读全文。“第三方组件”列出 Argus 包含的开源组件及其许可证与版权声明。“日志”记录系统与 WebView2 版本、传感器可用性、特权功能状态和固定的错误类别；操作失败时附上 Windows 错误码（例如 `access denied (os error 5)`），它不随系统语言变化。错误原文、堆栈、进程命令行、文件路径与用户名不会写入诊断日志；第三方库未经审查的日志不进入此文件。日志仅保存在本机的 `%LOCALAPPDATA%\dev.argus.taskmanager\logs\diagnostics`，`argus.log` 超过 1 MB 时轮换并保留一份旧文件；任务管理器替换的启动器另写 `taskmgr.log`。设置页的“打开日志文件夹”指向此目录。旧版本的日志留在父目录，不复制到新目录；提交缺陷报告时仅使用新目录中的诊断日志。
