# 原生界面

`src-gpui/src/frontend` 按界面职责拆分：layout 组织标题栏、导航和状态栏；tables 适配虚拟表格；menus 生成并绘制右键菜单；pages 提供进程、性能、服务、启动项、连接、历史与设置；dialogs 与 welcome 管理原生对话框及首次启动引导。

tables 按网格轨道分配列宽：固定宽度的列先占位，其余列按比例分配剩余宽度且不小于各自的最小宽度；进程表随宽度变窄依次隐藏线程与句柄、PID 与 I/O 列。表格本身不绘制背景，由外层工作区卡片提供图层色。右键菜单由 desktop 打开，menus 绘制菜单：文字随字体大小设置缩放，30 px 的行高、内边距、16 px 图标、分隔线与 220 px 的最小宽度保持像素值，菜单宽度取最宽一行；界面缩放整体放大。菜单在指针处打开，放不下时向左或向上展开，子菜单贴在所属项旁。交互规则：打开时第一项获得键盘焦点但不高亮，方向键移动并显示高亮，→、Enter 或单击打开子菜单，←、Esc 返回；指针悬停 250 ms 后打开或收起子菜单；禁用项悬停时同样高亮但不响应单击；菜单打开期间其他快捷键不生效；单击别处、窗口失去焦点或改变大小时关闭，关闭时淡出。图标使用 resources/ui-icons 中的 16 px 线性图标，随所在文字着色；其余图标取自组件库。界面字体：西文与数字用 Segoe UI Variable（大号数字用 Display 光学尺寸），界面字体缺少的字符（主要是中文）按 theme.json 中的顺序回退到 Segoe UI 和微软雅黑 UI；不指定回退时，英文系统区域下 DirectWrite 会用日文的 Yu Gothic UI 显示中文。悬停提示（`widgets::tooltip`、`widgets::wrapping_tooltip`，表格单元格的提示也用后者）由 GPUI 在根表面之外单独布局，继承不到根表面的回退字体与行高，因此各自设置：采用系统提示字体，西文用 Segoe UI，中文按 theme.json 回退到微软雅黑 UI，9 pt（12 px，随字体大小设置缩放），行高为该字体自身的行距（约 1.33 倍）。

tips 为表格单元格提供悬停提示，包括：进程名称的全称与路径、GPU 列的最忙引擎、网络列的发送与接收速率、缺少磁盘读数的原因、服务所在的进程、服务描述与启动命令、启动项不可更改或程序已不存在的原因、行备注与置顶标记、搜索时标题行不能折叠的说明，以及历史表中同名进程的描述。表格每个滚动帧都重建可见行，若每个单元格各带一个 `.tooltip()`，每帧会多出一个命中区域和四个鼠标监听。这里每个表格只转发指针移动，只有指针下的一行在布局时报告带提示的部分及其位置，由一个跟踪器找出指针下的部分；提示按 GPUI 提示的 500 ms 延迟出现，与 `.tooltip()` 共用窗口的提示位置与样式，同样在指针离开、按下、滚轮或键盘输入时隐藏。按下或滚动之后，直到指针再次移动，表格不再报告，滚轮滚动的帧与指针不在表格上时的重绘因此不增加元素。提示由根部的一个独立视图绘制，显示与隐藏只重绘它，不重建表格。

scrollbar 绘制所有滚动区域共用的滚动条，几何与样式：右侧 10 px 槽位、透明轨道，滑块四周留 3 px 透明边，显示宽 4 px 的圆角滑块，悬停或拖动时加宽到 6 px 并加深。内容超出时即显示；滑块长度与位置按设备像素取整，最短 17 px；拖动滑块直接定位，单击轨道向指针方向翻过可见高度的 87.5%，按住时重复。滚动条不参与布局，从滚动句柄读取范围与偏移，绘制在滚动区域的槽位上；需要稳定滚动条槽位的区域在右侧多留 10 px，内容居中时也按扣除槽位后的宽度计算。鼠标滚轮平滑滚动（GPUI 补丁，见 `vendor/gpui-pre/ARGUS-PATCHES.md`）：系统设置为每次 3 行时每格 100 px，在 100–200 ms 内按缓入缓出曲线到达目标，连续滚动时目标累加并保持当前速度；内层区域到达边缘后滚轮才交给外层。虚拟表格的滚轮在捕获阶段转为同样的滑动；滑动尚未到达边缘时，越过边缘的滚轮仍归这次滑动，不交给表格组件自身的滚轮处理（它按行距跳动并中断滑动，列表会停在边缘之前）。

model 负责应用分组、进程树、搜索、排序和源时间历史。身份由 PID 与创建时间共同确定。名称排序：collation 通过 Windows 自带的 ICU（`icu.dll`，首次使用时加载）按界面语言生成排序键并缓存，数字按数值比较，忽略大小写与重音；中文汉字按拼音排在拉丁字母之前，英文则拉丁字母在前。进程表、服务、启动、连接与历史表的文字列都使用它。各页面保留独立的选择、排序、搜索与表格状态。冻结排序只影响显示次序，数据继续更新。

desktop 是唯一的状态持有者，按区域绘制：标题栏、导航、当前页面，以及进程页的资源卡片与详情窗格各是一个缓存视图（regions），表格也各有缓存视图。desktop 的常规通知会重绘所有区域；区域内的动画帧、平滑滚动或悬停只重绘该区域，祖先视图只重建自身的元素并重放其余区域（GPUI 补丁，见 `vendor/gpui-pre/ARGUS-PATCHES.md`）。实时曲线归属于构建它们的区域。切换页面时，新页面按最终位置布局一次，进入动画的位移与淡入只作用于绘制（shift 模块的视觉变换），各帧重放已绘制的页面；动画期间命中测试按最终位置进行，曲线层随页面位移。动画从切换后绘制的第一帧开始计时。进程页的详情窗格打开或收起时同样如此：列表按整张卡片的宽度布局，只在绘制时裁剪到可见宽度（视觉裁剪，不改变内容遮罩，缓存视图得以重放）；窗格按打开后的位置布局，宽度变化与 24 px 的滑入、淡入只作用于绘制，窗格内的曲线随之移动、淡入并裁剪。两者在动画期间重放已绘制的内容，结束时按最终宽度布局一次。性能页切换设备时详情视图的移入与淡入同样只作用于绘制，滚动范围不随位移变化。列表的纵向滚动条因此由页面绘制，随可见边缘移动。CPU 视图在整体与多核之间切换、核心卡片随核心类型重排时更进一步：变换是实时的（`Window::with_live_transform`），图表层在每帧开始时更新其数值，页面所在区域重放已绘制的内容，过渡期间不重新渲染，结束后按最终排列渲染一次；图表层用同一组变换绘制其中的曲线。分段控件选中标记的滑动也用实时变换，滑动期间所在区域不逐帧渲染。

服务、启动与连接页的列表由各自的查询和行变更通知更新。新快照仅影响状态栏时，desktop 重绘自身并重放缓存页面，不连带重建工具栏、导航和表格；没有规则的设置页也采用同一方式。首次快照、传感器状态变化、含规则的设置页、打开的弹窗或菜单、拖动及隐藏状态仍完整通知。图标编号在同一 MetaStore 写入 PNG 后才发布，图标变化随列表或所属进程数据更新。该边界不改变采样、时间线、页面查询频率或状态栏数值的更新。

对话框按内容高度绘制，打开时在窗口中居中；之后内容变高或变矮（展开快捷键说明的分组、文件占用查询返回结果等）时保持上边缘不动，按 Fluent 的移动曲线在 167 ms 内伸缩到新高度，最多伸展到距窗口底边留出的边距（快捷键说明 24 px，更新 32 px，运行新任务 20 px，其余 16 px），更高的内容在对话框内滚动。伸缩期间内容区固定为对话框当时留给它的高度（少 1 px，抵消按设备像素取整的误差），放得下的内容因此不出现滚动条，滚动条只在高度停在上限后出现。窗口大小改变时重新居中。

区域内的元素测得新的位置后只重绘所在区域：分段控件的滑动指示、标题栏中搜索框两侧的控件（换页后页面控件的宽度不同）都是如此，只有标题栏放不下、需要逐级收起时才重绘整个 desktop。切换页面的第二帧因此只重绘标题栏，不再重绘页面中的表格。服务、启动与连接页进入期间，新的行和采样（这些页面中只有状态栏显示采样）等到进入动画结束后再绘制，动画期间只重放第一帧。

lists 生成服务、启动与连接列表的行（筛选、搜索、行标记与排序）。连接列表常有上千条，每两秒重新读取，所属进程的名称、描述与图标来自每次采样：读取结果由各次构建共享，行在后台线程生成，界面线程只安装结果；所属进程不变时，采样不重建连接行。回到连接页时，若上次的行按当前的搜索、筛选、排序与行标记生成，直接显示它们，之后的读取与采样在后台另行构建；首次进入前，启动后预读的连接列表已在后台生成行。搜索、排序、筛选与行标记的变化仍在界面线程上立即重建。

界面偏好在内存中立即生效，由后台线程写入磁盘，退出前写完；写入失败时提示一次，再次写入成功后才会重新提示。列表排序保存在 `tableSort.<表>`，服务与连接筛选分别保存在 `services.filter`、`connections.filter`；保持已有偏好键和列标识兼容。服务描述与启动命令列不支持排序。

appearance 处理界面缩放与字体大小。界面缩放通过 GPUI 补丁 `Window::set_content_zoom` 把缩放比例乘入窗口的缩放因子：视口按比例变小，文字、图标与曲线按设备像素重新栅格化，布局、绘制、指针与原生标题栏的命中测试使用同一坐标；窗口在屏幕上的位置、大小与最小尺寸不变（补丁见 `vendor/gpui-pre-windows/ARGUS-PATCHES.md`）。字体大小按基准字号换算：各处字号经 `theme::font` 按 13 px 基准换算，组件库的字号随主题变化；间距与控件尺寸保持像素值，由文字撑开的高度（状态栏、表头、性能页的设备行）随字号的行高增加，资源卡片的数字不超过卡片内容宽度的 33%，放不下的单位延伸到相邻卡片，不在卡片内截断。标题栏逐级收起（页面控件或右侧按钮越过搜索框的最小宽度、或越过标题栏按钮前的边距时）：先隐藏右侧按钮的文字，再隐藏视图切换的文字，再把页面控件移到第二行，最后把搜索框移到单独一行；每级记住放不下时所需的宽度，窗口足够宽时逐级恢复，换页、语言、字体大小、导航位置，以及更新按钮或历史页“回到最新”按钮出现或消失后重新计算。

文本框样式由控件类型决定（`widgets::text_field`）：普通文本框为控件底色、1 px 描边与较深的底边，获得焦点时底边换成 2 px 强调色；运行新任务的命令框没有底色与边框，获得焦点时显示 2 px 强调色外框，运行期间禁用时外观不变，对话框保留滚动条槽位。占位文字由界面绘制在输入内容之下，使用界面字体和次要文字色（组件库自带的占位文字跟随输入框的字体，颜色也较浅）。设置中的数字框带有增减按钮：指针悬停或获得焦点时显示在文字末端，宽 15 px，两个箭头为圆角三角形，作为颜色图像按面积过滤绘制（单色图标套用文字的对比度增强，会把这么小的箭头画粗）。按下时立即步进一次，250 ms 后每 50 ms 重复一次，方向随指针所在的一半改变，移出按钮时暂停，松开时提交；↑/↓ 键步进后立即提交。步进规则：不是数字的内容从最小值开始，超出范围的值先回到较近的一端，小数取到步进方向的下一个整数。

type_search 让进程页的输入法输入从第一个按键起进入搜索框。输入法只为提供了输入上下文的窗口组字，且在应用读到按键之前处理它；GPUI 的 Windows 平台在没有获得焦点的文本输入的帧之后移除窗口的输入上下文，所以在按键处理中再把焦点移到搜索框已经太晚，第一个按键原样到达，组字从第二个按键才开始。进程页的焦点不在输入框中、且没有弹窗或菜单时，desktop 每帧最先登记一个代替列表的文本输入（`SearchComposer`），窗口因此保留输入上下文；随后绘制的、获得焦点的文本输入会取代它。组字开始时搜索框获得焦点，插入点移到原有内容之后，组字文字转交搜索框，候选窗口按搜索框文字的末端定位；之后的组字消息直接到达搜索框。组字之外送出的文字（输入法直接送出的标点、未处理的按键产生的字符）不进入搜索框；未经输入法处理的字母和数字仍由按键处理开始搜索。取消的组字不改变搜索框内容，焦点回到原处。打开进程页后焦点不在任何元素上时，焦点移到页面根部，键入前不必先单击。输入法仅以 `WM_IME_ENDCOMPOSITION` 结束组字时（`ImmNotifyIME` 的 `CPS_CANCEL` 即如此），GPUI 补丁清除仍标记为组字中的文字（见 `vendor/gpui-pre-windows/ARGUS-PATCHES.md`）。

charts 使用 GPUI 原生曲线组件与路径缓存。不同数据源、单位、主题、语言或序列变化时才更新图形；滚动时移动已有几何路径。静态表格与曲线实体隔离，避免动画重复构建表格。

theme 从 resources/theme.json 读取色板、字体与行高，界面文案从 locales 读取；窗口大小、标识和公钥来自 resources/app.json。硬件设备、拓扑、量程和可用字段从实时快照产生，不根据开发机型号写分支。

文字的行高默认为字号的 1.4 倍，由窗口的根表面继承到页面、对话框与通知；新建任务的说明、更新内容、快捷键说明、代码与许可证文本、引导说明等元素分别设置行高。GPUI 自身的默认行高约为 1.6 倍，沿用它会使多行说明及由其撑开的卡片偏高。文字换行遵循 UAX #14 及 ICU 的中日文调整规则（GPUI 补丁，见 `vendor/gpui-pre/ARGUS-PATCHES.md`）：行首不出现 `。`、`，`、`、`、`）`、`」`、`”`、`：`、`……` 等，行尾不出现 `（`、`「`、`“` 等，汉字与英文单词、数字之间无空格也可换行；两个 ASCII 字符之间仍按 GPUI 的规则，只在空格处及部分符号前换行。

inline 把元素排进文字的行内：本机配置提示中的面板按钮，以及引导与快捷键设置里句中的键帽（`Desktop::rich`）。GPUI 的文本没有行内盒，这里用一个与元素及其外边距等宽的不可见拉丁字母单词占位：单词内部不断行，元素因此整体随文字换到下一行（只在两侧的空格处断开），并绘制在占位单词排到的位置。面板按钮在基线下偏移 4 px；GPUI 的各行等高，因此在文字下方保留容纳按钮的余量，按钮不在最后一行时则不越出本行；键帽在行内居中，行高不小于键帽。GPUI 换行时行尾空格计入行宽。

文本向布局报告首行基线（GPUI 补丁），`items_baseline` 因此对齐文字基线：性能页、资源卡片、GPU 引擎与核心格中的数值与较小的单位，性能页标题与右侧的型号，以及卡片标题与说明。未经补丁的 GPUI 不报告文本基线，布局把没有基线的元素视为基线在底边，`items_baseline` 对齐的只是框的底边，字号与行高不同的数值和单位因此错开 1–3 px。基线取整到设备像素，对齐的文字按同样的方式取整，绘制时落在同一像素行。
