# 原生界面

[`src-gpui/src/frontend`](../../src-gpui/src/frontend) 包含窗口布局、虚拟表格、图表、菜单、对话框和各页面。`Desktop` 持有界面状态，采样与系统操作由[原生宿主](host.md)调度。

## 数据、排序与偏好

`model` 以 PID 和创建时间标识进程，生成应用分组与进程树。各页面独立保存选择、筛选和排序。`collation` 用 Windows 的 ICU 按界面语言生成排序键，数字按数值比较，字母忽略大小写与重音。暂停排序期间行位置固定，数值继续更新；展开或折叠时同样保持，新显示的行跟在所属条目之后（`Desktop::holds_order`）。

`lists` 生成服务、启动项与连接的表格行。连接数据每两秒读取一次，进程名称和图标来自采样。后台线程根据新连接或所属进程变化准备行，界面线程接收结果。再次进入时，筛选、搜索、排序和备注仍匹配的缓存可直接显示。

`process_icons` 按当前快照保留程序及 WebView2 宿主的图标，表格、详情窗格和规则界面共用同一份图像。快照替换后，过期图标同时从 GPUI 解码缓存和窗口纹理图集中移除，GPU 页面可随之回收；暂停时继续持有原快照的 PNG。

界面偏好在内存中立即生效，由后台线程写入磁盘，退出前完成写入。`tableSort.<表>` 保存各表排序，`tableWidths.<表>` 保存服务表与启动项表中拖动过的列宽，`services.filter` 和 `connections.filter` 分别保存服务与连接按状态的筛选条件，`connections.protocolFilter` 保存连接按协议的筛选条件，`connectionView` 保存连接页的视图（`list` 或按应用分组的 `apps`），`openedConnectionApps` 保存按应用视图中展开的分组（规范化的可执行文件路径，路径缺失时使用小写文件名）。

性能页的 `cpuKernelTime` 保存 CPU 图表是否叠加内核时间，默认开启。`perfHiddenDevices` 保存设备列表中已隐藏设备的标识（`performance/rail.rs` 的 `stable_key`）：磁盘为总线、型号与容量，网络适配器为适配器型号与连接名称，显卡为名称，电池为名称与序列号；标识相同的设备按列表顺序追加序号。磁盘编号和适配器 LUID 随插拔顺序与重启变化，不用作标识。列表至少显示一项：保存的选择隐藏了当前全部设备时显示第一项。

## 表格、滚动与提示

`tables::groups` 由进程行求出用户与分类分组的行范围和颜色（`Tone`，色值为主题的 `group-*`），并在列表之上、页面绘制的滚动条之下绘制固定在顶部的分组标题、滚动条旁的分组标记与组名。它们由表格行所在的视图（`TableBody`，组件绘制行时为表格框架 `TableFrame`）画在列表之外，不随行重排；滚轮平滑滚动在列表自身的预绘制阶段推进偏移，固定标题与组名在各自的预绘制阶段按推进后的偏移重新定位（`Follow`），与行在同一帧对齐。固定标题以不透明底色遮住下方的行，阻止其悬停与点按但保留滚轮。

`tables` 的表头使用组件库的 `DataTable`，可见行由 Argus 自行虚拟化和绘制（见下）。进程表的名称列固定在左侧，其他列按保存的顺序排列。自动宽度测量表头与汇总值，表头另计组件为排序图标保留的右侧内边距；百分比、内存、速率等数值列及其汇总值先按格式的常见最大值预留宽度（`tables::widths::envelope`），其他列测量完整的进程列表（`tables::WidthRows`）：全部分组展开、不含搜索条件，与显示的行分开生成，每行只保留名称单元格的组成和各列文字（`WidthRow`），不保留进程数据。列表在后台线程生成：随采样最多每 5 秒一次；切换视图、名称排序、分组方式、所选列或语言时立即生成，完成前沿用原列表。搜索与折叠只改变显示的行，不触发重新测量；两次生成之间只测可见行，且只加宽。数字按等宽字形测量，数值列只增不减并按 8 px 取整。名称、路径等文本列记录两个宽度：多数行所需（四分位距上界以外的行视为过长，且至少容纳 95% 的行）和全部行所需（`Natural`）；`widths::allocate` 先给每列前者，再把表格剩余宽度按各列差额比例分配，至多到后者，不拉伸任何列。文本列收窄超过一档才更新。拖动过的列在 `processColumns.overrides` 中保持手动宽度，不参与分配，其他列宽度不受影响，双击列边界移除；“全宽”让未拖动过的名称列取剩余宽度。表头的列边界由组件的调整手柄接管悬停，Argus 在表头放置画布并以窗口级鼠标事件判断指针所在的边界（`header::edge_probe`），绘制提示线。宽度变化由 `TableFrame` 逐帧插值（`WidthGlide`），窗口尺寸、字号或语言变化时直接应用。字号或语言变化时重新测量。拖列表头或滚动期间冻结宽度，汇总值在各自列内裁剪并同步滚动。服务表与启动项表按同样的方法测量载入的完整列表（`AutoWidths::apply_list`，不受搜索与筛选影响）：名称、服务名称与发布者记录多数行与全部行所需的宽度，PID 与位置取全部行所需，状态、启动类型等标签列取最宽的标签（`fit_fixed`）。最后一列（描述、命令）不可拖动，取其余各列剩下的宽度（`widths::fill`）：不足表格宽度的三分之一（且短于其最长内容）时，文本列先按差额比例收窄到各自的下限；仍不足该列下限时，拖动过的列也让出宽度，之后才出现横向溢出；超出其最长内容所需时，文本列加宽至完整显示全部行。拖动列边界时 `TableFrame` 按拖动中的宽度重新分配，最后一列随之伸缩；可拖宽的上限是最后一列与其他文本列能让出的宽度。松开后宽度存入 `tableWidths.<表>`，双击列边界移除。进程表头由 Argus 自行处理拖动：越过相邻列中线即交换并保存顺序，换位的列由 `flip` 从原位置滑到新位置；移动中的单元格内容以表格可视区为裁剪范围延后绘制，不受单元格自身裁剪。

表格每次重建都重新布局全部可见单元格，节点数决定一帧的开销。组件的表格为每个可见单元格建两层包装，并把每行的横向滚动列作为一个独立布局（每格一个布局根）。`tables::body` 改由 Argus 绘制行：组件的表格只绘制表头，行放在独立视图 `TableBody` 中，每行仍是同样的行元素（底色、悬停、选中与右键标记、单击和右键），行内的单元格由一个元素放置：名称单元格按原有布局排一次，横向滚动的各列按组件的算法求出位置与设备像素取整后直接绘制，带状态点、开关或标签的单元格保留各自的元素。名称单元格与带标记的单元格里不响应输入的方框用 `plain` 构建：样式与 `div` 相同，布局、裁剪和填充一致，但不带交互状态；只含一行文字的方框（名称、镜像名、分组标题）与文字合为一个布局节点（`PlainText`），名称单元格的外框与内边距框合为一个。展开按钮、开关、图标和图片仍是各自的元素。键盘移动选中行由 `TableFrame` 先于组件处理。辅助技术读取窗口、拖动列和列换位动画期间仍由组件绘制行，两种绘制逐像素相同。发布构建、1240×800 窗口与固定快照下，进程列表纵向滑动的一帧从约 4.5 ms 降到 2.3 ms，滚动期间界面线程的 CPU 时间减少约四成。

只显示一行文字的单元格（读数、PID、路径、说明、分类标题的合计等）由 `tables::cell_text` 绘制：它按带内边距的 flex `div`、`truncate()` 包装与文字节点的布局规则放置文字，设备像素位置、对齐、省略号截断、裁剪和提示区域都与这些节点相同，不再测量文字。单元格的文字、颜色、热度底色与字体按行缓存（`cells::CellValues`），名称单元格所需的成员计数、图标和标记也按行计算一次（`NameFacts`）；行列表、页面、单位、主题、字号或语言变化时重新生成，滚动与悬停不再读取进程数据。

`scrollbar` 从滚动句柄取得范围与偏移，在内容边缘绘制滑块。拖动可直接定位，单击轨道翻过 87.5% 的视口。虚拟表格的纵向滚轮、横向滚轮和 Shift+滚轮共用平滑滚动，内层到达边缘后再由外层处理。实现见 [GPUI 补丁](../../vendor/gpui-pre/ARGUS-PATCHES.md)。

`tips` 由每张表统一跟踪指针，只让指针下的行报告名称、读数或说明的位置。指针移到另一行时表格不重建：在该行停留 250 ms 后表格重建一次，由该行报告；快速划过的行不触发重建。提示在指针进入该部分 500 ms 后由独立视图显示，等待重建的时间计入其中；按键、按下鼠标、滚动或离开时隐藏。菜单由 `menus` 在指针附近布局，靠近窗口边缘时调整方向。方向键可移动焦点和进入子菜单，Esc 返回。菜单及其子菜单关闭时直接消失，不播放退出动画；菜单打开期间，表格与控件的悬停提示都不显示。

## 区域绘制与曲线

`regions` 分别缓存标题栏、导航（顶部导航时连同页面栏）、侧边导航时的页头、页面、表格和进程页的概况带与详情窗格。区域内的滚动或动画只重绘相关区域，其余区域重放上一帧的绘制结果；随整个桌面一同重放过的区域，之后仍可单独重放。表格纵向平滑滚动的各帧只重建行所在的视图（行、固定分组标题与组名，其他表格连同纵向滚动条），表头、页面区域和桌面不重建自身的元素树，重放上一帧的绘制结果，行在原位置重新绘制；横向滚动的各帧重建整张表格。滚轮每转一格的那一帧仍完整重建。进程页的纵向滚动条由页面区域绘制，滑动期间页面区域随之逐帧重建。

新采样只重建显示它的部分。进程页重建列表、概况带和状态栏；详情窗格显示所选进程时随采样重建，显示本机配置时仅在硬件信息变化后重建。性能、历史等页面重建页面区域和状态栏，服务、启动和连接等页面只重建状态栏。标题栏与导航不随采样重建。传感器状态变化、弹窗或菜单打开及拖动期间，采样仍重建整个窗口。新的列表行、弹窗或布局变化按需重建相应内容。

悬停、按下、松开以及提示的出现和消失只重绘元素所在的视图。表格和详情窗格以 `hover_fills_in_place` 标记：其中悬停样式只改变底色的元素（列表行、详情条目和按钮）直接修改已呈现画面中的底色并提交，不重建视图。这两处随指针变化的内容自行请求重绘：单元格提示由 `tips` 在指针停稳后请求，带动效的图标由 `icon_probe` 自带的悬停样式触发。实现见 [GPUI 补丁](../../vendor/gpui-pre/ARGUS-PATCHES.md)。

切换页面和性能设备时，先按目标位置布局，绘制时再滑入。页面滑入从新页面首次呈现的那一帧起计时：新页面的第一帧要完整布局与绘制，性能页还要先测量布局而不呈现，若从切换时刻计时，页面一出现就已滑过大半距离。页面与导航选中标记的移动都用 250 ms；页面不淡入，曲线取 ease-out cubic，Fluent 的入场曲线把位移集中在开头，交给淡入掩盖。详情窗格和多核网格用实时变换重放画面，图表与所属区域在同一帧移动和裁剪。`ChartLayer` 在滚动帧平移缓存的曲线纹理，更新数据或绘制样式时重新栅格化。图层、显存预算和量程变化见[曲线与时间轴](../design/charts.md)。关于页的点阵（`hundred.rs`）由图表层之上的 `HundredLayer` 绘制，页面只留出位置并记录其边界与裁剪范围：开场动画的各帧与每次采样只重绘该图层，不重新布局页面。

## 对话框与输入

对话框打开时居中。首次测量正文与页脚高度的那一帧不呈现：组件在尚未定位时把对话框画在视口高度的十分之一处，且以自身的不透明度覆盖表面样式，呈现出来就是一闪而过的错位。对话框从首个可见帧起由 96% 放大到原尺寸（250 ms，曲线 `cubic-bezier(0, 0, 0, 1)`），前 83 ms 线性淡入；关闭时缩小到 96%（167 ms，同一曲线），100 ms 内线性淡出后移除（`dialogs/presence.rs`）。云母窗口在首个对话框出现时显示主题遮罩，最后一个对话框淡出完成时移除。开关嵌套对话框时，底层遮罩保持原亮度。实色窗口的遮罩在 167 ms 内线性淡入或淡出。组件以自身的不透明度与投影覆盖表面样式，缩放和淡入淡出因此放进样式携带的变换（`Styled::paint_transform`，见 [GPUI 补丁](../../vendor/gpui-pre/ARGUS-PATCHES.md)），表面的投影、底色、边框与内容一同变换；静止时不带变换，文字按整像素绘制。关闭“界面动画”后对话框与遮罩直接出现和消失。表单在异步查询返回或展开说明时保持顶部位置，高度在 167 ms 内过渡到新值；更新和更新内容窗口在内容加载、展开及高度过渡期间保持居中；其中的版本展开或折叠时由内容自身过渡高度，时长与曲线沿用官网更新日志（每像素 1.6 ms，限于 240–420 ms，`cubic-bezier(0.2, 0.8, 0.2, 1)`），窗口在此期间直接跟随内容高度，不再叠加自身的过渡；悬停高亮与入场动画同样使用这条曲线。达到窗口可用高度后，正文使用带持久滚动句柄的原生滚动容器，滚轮沿用页面的平滑动画，页脚固定。调整窗口大小会重新居中。

对话框的正文与页脚测量忽略小于 1/64 物理像素的高度差，避免分数缩放下的浮点误差反复触发布局和高度过渡。内容增减及窗口尺寸变化仍按实际测量更新。

`widgets::text_field` 统一文本框的焦点与边框样式。输入元素由 `widgets::input` 构造，右键菜单为系统原生菜单，剪切、复制、粘贴和全选的文案取自 `common.edit`，随界面语言切换。数字框支持单击和长按增减，方向键步进后立即提交。进程页的 `SearchComposer` 在列表获得文字输入时为输入法保留输入上下文。开始组字后将文字和焦点交给搜索框；取消时恢复原内容与焦点。弹窗、菜单与已聚焦的输入框优先处理按键。

## 缩放与排版

`appearance` 使用 `Window::set_content_zoom` 将界面缩放与 Windows DPI 合并，布局、绘制和命中测试共用坐标。字体大小按 13 px 基准单独换算。概况带根据卡片宽度调整大号数字和单位，辅助读数排成一行，空间不足时缩小字号。标题栏只有标识、搜索框与窗口按钮，搜索框宽度随窗口宽度变化。窄窗口时页面栏先把带文字的选项改为下拉按钮，再把页面控件移到下一行；级别按实际测得的宽度判断，随语言和字号变化。每个页面（连同字号、语言与导航位置）记住各级别所需的宽度，切换回来时直接按当前宽度选定级别；尚未测得时，放不下的级别所画的帧只测量布局、不呈现（`Window::defer_presentation_until_layout`），控件不会先出现在行尾再跳到下一行。

`theme` 从 [`theme.json`](../../resources/theme.json) 读取色板、字体和行高。西文使用 Segoe UI Variable，大号数字使用 Display 光学尺寸，简体中文回退至微软雅黑 UI。选中标签和分组标题使用 500 字重。提示框单独设置系统提示字体和行高。正文默认行高为字号的 1.4 倍，换行采用 UAX #14 与 ICU 的中日文调整规则。

文字抗锯齿采用 DirectWrite 的亮度自适应对比度校正：额外增强在前景亮度 50%–75% 之间逐渐减弱，更亮的文字保留原始覆盖率与 Gamma 校正。深色背景上的浅色文字据此避免边缘额外加厚，Markdown 的加粗字重和强调层级保持原设定。参考 [DirectWrite 混合实现](https://github.com/microsoft/terminal/blob/1283c0f5b99a2961673249fa77c6b986efb5086c/src/renderer/atlas/dwrite.hlsl)。

界面统一启用字体的等宽数字特性（`tnum`），文本测量使用相同设置。进程列表、性能读数、图表标注、详情、状态栏和提示框中的数字在位数及格式相同时保持宽度，避免刷新时横向跳动。进程 CPU、GPU 列及分组汇总值显示百分号，自动列宽为百分号预留空间。

字形按 DirectWrite 为该字体、字号和缩放推荐的渲染方式栅格化，与 Windows 和 Chromium 一致：微软雅黑 UI 的字号不超过 21 设备像素时按字体的网格对齐仅做水平抗锯齿，更大时双向抗锯齿；Segoe UI Variable 始终双向抗锯齿。行的上伸与下伸取文字所请求字体的度量，不取回退字体，纯中文、纯西文与中西混排在相同行高中基线一致。云母窗口将 DirectWrite 的子像素覆盖率按亮度加权为灰阶遮罩，合成时应用系统对比度和伽马。整窗实色模式可按系统设置使用 RGB ClearType。区域级 ClearType 方案及取舍见[窗口外观](../design/window.md)。

`inline` 用等宽占位将按钮和键帽嵌入一行文字，使控件随文本整体换行。数字与单位、标题与型号按首行基线对齐，基线取整到设备像素。相关补丁见 [GPUI](../../vendor/gpui-pre/ARGUS-PATCHES.md) 和 [Windows 平台层](../../vendor/gpui-pre-windows/ARGUS-PATCHES.md)。

## 辅助技术

屏幕阅读器等辅助技术经 AccessKit 读取窗口，有客户端读取时 GPUI 才构建辅助功能树。带 id 与角色的元素是树中的节点；没有 id 的文字（字符串、`StyledText`，以及 Argus 自行排版的 `PlainText`、`CellText` 和 `InlineText`）在预绘制时经 `Window::report_a11y_text` 报告，按所在的最近节点归属：按钮、页签、菜单项、单元格等控件没有自己的名称时以文字为名称，名称未包含的文字作为说明；组合框以文字为值；其他位置的文字成为独立的标签节点，按所在元素 id 路径中的序号编号，文字本身或其他路径中的内容变化时节点不变。`visibility: hidden` 方框中的文字（如下拉按钮中为测宽保留的其他选项）不报告。`InlineText` 的句子含占位词，改为按原文顺序报告各段文字与其中的元素。文本框的占位提示以 `Text::new_inaccessible` 绘制，输入框本身已用同一文字命名。

区域重放的帧不携带辅助功能节点，这样的帧不发送树：辅助技术保留上一棵完整的树，随后补绘一帧完整画面，停顿后立即补绘，动画持续时至多每 250 ms 一次；焦点变化本身就完整重绘。辅助技术读取窗口期间，表格行由组件绘制（`NativeTable::draws_rows`），单元格以文字为名称。实现见 [GPUI 补丁](../../vendor/gpui-pre/ARGUS-PATCHES.md)。
