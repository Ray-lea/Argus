# 原生宿主

`src-gpui/src/lib.rs` 负责应用启动，先处理安装、任务启动、服务和任务管理器辅助模式，再加载设置、诊断日志、单实例通信、采样器与 GPUI 窗口。

平台宿主管理窗口、托盘和全局快捷键。窗口最小化或隐藏时，曲线暂停绘制，采样按相应的后台间隔继续。恢复窗口时请求新快照，按采样时间显示这段间隔。

宿主的 `argus-restored` 事件区分托盘隐藏、最小化和本进程首次显示。界面按 `trayPage` 偏好处理后续托盘恢复：默认保留当前页，选择 `default` 时打开 `startPage` 指定的默认页；未关闭的对话框保留原上下文。首次显示沿用启动页选择，因此更新重启仍回到更新前的页面。

文件拖放由前端的 OLE 接收与 Windows 原生文件消息共同接入。管理员窗口使用原生文件消息通道接收普通权限程序的文件投递；解码限制文件数量、单路径长度及总长度，随后交给现有文件占用查询。窗口销毁时移除消息子类并释放宿主引用。接口见 [DragAcceptFiles](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/nf-shellapi-dragacceptfiles) 与 [ChangeWindowMessageFilterEx](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-changewindowmessagefilterex)。

`window_motion.rs` 让窗口在显示、隐藏到托盘、最小化和还原时原地淡入淡出（显示 180 ms，离开 140 ms），由独立的 `motion.window` 偏好控制。开启期间仅在淡入淡出进行中和窗口最小化或隐藏时抑制 DWM 窗口过渡，使各种还原途径都以淡入呈现；窗口显示期间保留 DWM 过渡，最大化、从最大化还原和贴靠沿用系统动画；关闭时结束当前淡入淡出、移除自身的临时透明样式并停止时钟，释放 DWM 过渡及原生最小化／还原消息的处理。其他线程的请求转到窗口线程执行；标题栏的最小化按钮发送 `SC_MINIMIZE`，开启时任务栏还原和其他程序直接显示窗口也会淡入。

`crates/argus-app/src/preferences.rs` 将界面偏好与窗口位置原子保存到配置目录的 `preferences.json`，同一配置目录下的启动入口共享偏好。文件沿用 v0.3.3／v0.3.4 的布局：偏好保存在 `values`，窗口位置保存在 `window`，更新时保留其他配置。从 v0.3.2 及更早版本直接升级时，旧 WebView2 缓存中的界面偏好恢复默认值，详见[升级说明](../guide/settings.md#旧版升级与数据)。`src-gpui/src/window_state.rs` 保存 `WINDOWPLACEMENT` 的普通窗口矩形与最大化标记，移动或缩放结束后保存，关闭和退出前补写；隐藏启动延迟到首次显示时恢复最大化，不恢复最小化状态；测试实例不恢复窗口位置。

恢复跨显示器的位置可在 `SetWindowPlacement` 内同步触发显示器变更回调。GPUI 上下文正在更新时，窗口将这些通知合并并延后处理，释放借用后读取最新显示器及刷新间隔，避免原生回调重入导致启动崩溃。上下文空闲时仍立即处理通知。

`admin.rs` 在创建窗口前处理管理员启动和权限交接。设置页立即应用切换，引导在结束时应用，详见[管理员启动](administrator-startup.md)。登录启动项使用受保护的管理员启动器或应用程序本身。安装和卸载前，`argus.exe --argus-close-copies` 结束管理员启动和任务管理器替换目录中的界面副本，释放单实例锁和待替换的文件。

`native_runtime.rs` 管理进程内状态、合并通知并调度主线程。`commands.rs` 将界面请求分派给应用服务，耗时操作在工作线程完成。

托盘的创建、提示与图标更新由独立线程调用 Windows Shell，采样线程和界面只提交最新状态。Explorer 卡顿期间不累积旧提示，恢复后应用最新状态；`TaskbarCreated` 通知与后续更新负责重建托盘图标。退出时给予删除请求最多 100 ms 的等待时间，托盘故障不会阻止窗口退出。

实时托盘图标（`shell/tray_icon.rs`）在托盘线程中按 `SM_CXSMICON` 的尺寸绘制：眼睛与负载条以有符号距离加一像素边缘绘出，数字由 GDI 灰度抗锯齿文字取覆盖率；新样本画出的像素与当前图标相同时沿用原图标，不调用 Shell。字形颜色读取 `SystemUsesLightTheme`，在 `WM_SETTINGCHANGE` 时更新。图标添加后切换到 `NOTIFYICON_VERSION_4`：回调的低位为事件、`wParam` 为锚点坐标，右键单击以 `WM_CONTEXTMENU` 到达，悬停以 `NIN_POPUPOPEN` / `NIN_POPUPCLOSE` 到达；开启悬停卡片时不设 `NIF_SHOWTIP`，系统提示让位于卡片，提示文字仍供读屏使用。

悬停卡片与快捷面板（`frontend/tray.rs`）共用一个 GPUI 弹出窗口（`WindowKind::PopUp`），提前创建并在两次使用之间隐藏：新建窗口要建立渲染器、交换链和字形图集，开发构建还要现场编译着色器，在 i5-13500HX 上发布构建约 30 ms、开发构建约 0.6 s，而显示已有窗口到开始淡入约 10–20 ms。托盘图标收到指针移动（`WM_MOUSEMOVE`）时立即创建，窗口隐藏到托盘或以托盘方式启动后 1.5 s 创建；创建后在屏幕外以完全透明排一次快捷面板，预先完成文字排版、字形栅格化并记下高度。隐藏的窗口约占 13 MB 私有内存，随“隐藏时释放内存”一并释放，之后由指针移到托盘图标时重新创建。宿主以 `Shell_NotifyIconGetRect` 和所在显示器的工作区计算锚点（`shell/tray_anchor.rs`），弹出窗口先以上次的高度完全透明显示并完成布局，高度不同时按内容高度与客户区（不含不可见边框）重新定位到托盘图标旁、离任务栏 12 px 处，然后以分层窗口的不透明度淡入；窗口不受非活动窗口的帧率上限约束，淡入淡出按显示器刷新率绘制。面板在测试实例外取得前台，失去激活时关闭。打开期间采样器的窗口探针按“显示”计算间隔，读数随前台刷新频率更新。

托盘 GUID 由应用标识和规范化的程序路径稳定派生，创建、修改、Explorer 重建和删除均携带同一 `guidItem` 与 `NIF_GUID`。版本、提示文字、语言和更新角标不参与标识计算；同路径覆盖升级沿用已有标识，开发／测试标识和不同程序位置相互隔离。Windows 将托盘 GUID 与程序路径绑定，参见 [NOTIFYICONDATA 的标识与路径规则](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/ns-shellapi-notifyicondataw#troubleshooting)。

图表按物理可用内存、进程可提交内存以及所在作业的提交限额调整栅格预算。可用余量低于 32 MiB 时释放原有纹理、降低栅格精度，并将并发工作缓冲限制为 4 MiB，为采样和操作保留分配空间；大图表按像素预算继续缩小。实时读数、曲线数据、平滑与填充保留，余量回升至 64 MiB 后恢复原有精度。

`disk_details` 按物理磁盘编号读取身份、PCIe 链路及可用的健康字段。NVMe 和通用存储属性在本地读取，ATA／SAT／SCSI 的扩展身份与健康查询由已运行的特权服务补充。每次请求读取一次，周期采样只更新常规磁盘指标。返回结构和单位见[磁盘详情接口](core.md#磁盘详情接口)。

配置目录保存 settings.json 与 preferences.json，本地数据目录保存历史、更新文件和诊断日志。发布版标识来自 resources/app.json，开发版追加 .devbuild 与稳定的工作区指纹，不同工作区独立保存设置与单实例锁；测试也可显式指定独立标识。

相同故障持续出现时，诊断日志按 1、2、4、8、15 分钟逐步延长重复报告间隔，之后最多每 15 分钟报告一次；`suppressed_repeats` 表示期间合并的重复次数。每个故障独立限频，新错误立即报告，同一故障静默一分钟后重置间隔。服务未运行时的查询与传感器状态合并报告，新注册服务的 1077（尚未启动）按正常停止状态处理。

0.1.0–0.3.4 用 WebView2 显示界面，在本地数据目录留下浏览器数据 `EBWebView`；0.3.x 以其他管理员账户运行时，改在桌面账户的本地数据目录下写入 `WebView2\elevated-*`。`leftovers.rs` 每次启动时检查当前标识下的这两个目录，存在时由后台线程删除，不推迟窗口显示；遇到链接只移除链接本身，不删除其目标。仍在退出的 WebView2 进程占用文件时，其余部分留待下次启动，失败阶段与错误码写入 `argus.log`。以其他管理员账户运行时只检查该账户的目录，桌面账户下的 `WebView2` 在该账户自己启动 Argus 时删除。

`crates/argus-app/src/explorer.rs` 按桌面窗口、系统映像路径、会话、PID 与创建时间核对资源管理器。关闭前先创建主线程挂起的新 Explorer，以旧桌面进程为父进程继承原账户的令牌，并校验新旧进程的账户、会话、提升状态与完整性级别一致。普通权限和高权限桌面均按原权限重建；高权限桌面要求 Argus 已以管理员权限运行，也支持没有拆分令牌的管理员账户。进程和线程对象的访问控制与完整性级别也取自桌面令牌，避免管理员创建的对象阻止普通账户继续管理资源管理器。准备失败时保留原桌面并清理未启动的替代进程。

替代进程准备好后，Argus 向任务栏请求退出，等待最多五秒。旧桌面仍在运行时，使用事先打开的句柄结束该实例，再等待最多五秒确认退出。Windows 已恢复桌面时使用该实例，否则启动准备好的 Explorer。新桌面与任务栏持续一秒响应消息后报告完成。进程结束入口会识别当前桌面 Explorer，文件占用对话框也为它提供“重新启动”。

`crates/argus-app/src/tasks.rs` 处理“运行新任务”和安装后的启动。管理员权限的进程以普通权限启动程序时，辅助进程 `argus.exe --argus-run-task` 作为桌面外壳进程的子进程创建，继承外壳的令牌：账户原有的标准令牌，属于交互登录会话，盘符映射和设备命名空间与桌面一致。以父进程方式创建的子进程沿用创建者的环境变量，辅助进程因此在启动目标之前按自身账户重建环境。没有可用的外壳进程或无法创建辅助进程时，改用从当前令牌过滤出的标准令牌；该令牌仍属于提升的登录会话，读取不到其 DOS 设备目录，映射的网络驱动器也不同。“运行新任务”的辅助进程已创建时，仅在它自行报告未启动目标（外壳已提升，或无法重建环境）后才改用其他方式；其他退出码，包括崩溃，均作为启动结果报告，目标不会启动两次。安装后的启动在辅助进程失败或崩溃时仍改用过滤令牌：重复启动的 Argus 只会转交给已运行的实例。

“运行新任务”只使用与 Argus 同一账户且未提升的外壳，其余情况使用过滤令牌，任务保持 Argus 所在的账户。安装程序完成页的“启动”与应用内更新后的重新启动（`argus.exe --argus-launch-installed`）交给桌面账户的外壳：UAC 采用其他管理员的凭据时，Argus 仍以桌面账户运行，令牌和登录会话与之后从快捷方式启动时相同。外壳自身已提升（关闭 UAC 或内置 Administrator 账户）时直接启动，结果与该环境下的其他启动方式一致。

更新器负责下载、取消和安装前复验。客户端用 `resources/app.json` 中的公钥验证安装包与更新说明的签名，并核对签名绑定的版本。安装程序退出运行中的界面副本，更新已有管理员启动记录并刷新特权服务。通过管理员启动或任务管理器替换运行的安装版仍可应用内更新，免安装版提供下载入口。`--argus-updater-check` 在启动界面前返回安装类型，供打包流程检查。

平台职责与 macOS 边界见[GPUI 开发](../development/gpui.md)。

界面的系统进程隐藏借鉴 [System Informer 的筛选实现](https://github.com/winsiderss/systeminformer/blob/32ef60573927b26a153df29c258e63db15ab4f7c/SystemInformer/mwpgproc.c#L399)：依据进程元数据筛选展示结果，并保存筛选状态。System Informer 使用 Windows 签名，未启用签名查询时按 Microsoft 公司名称筛选；Argus 复用已有的 `windowsProcess`（系统目录、Windows 产品与公司信息，或内核伪进程身份），避免额外采集或验签。`frontend/visibility.rs` 处理可编辑的例外和额外隐藏名单，筛选在应用分组与进程树构建之前执行；连接列表的缓存输入包含筛选规则与归属进程的 Windows 标识，规则或身份变化后重新构建。
