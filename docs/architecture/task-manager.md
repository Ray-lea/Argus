# 系统任务管理器替换

Argus 提供默认关闭的系统任务管理器替换。界面入口在“设置 → 权限”，只在发布版且特权服务授权给当前账户时允许开启。开启需要管理员授权；关闭优先使用特权服务，服务不可用时使用管理员维护助手。当前实现尚未完成真实 IFEO、跨账户与安装包卸载验收，不应将普通权限下的测试视为这些场景已经通过。

## 启动路径

固定修改 `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Image File Execution Options\taskmgr.exe` 的 `Debugger` 值，类型为 `REG_SZ`，内容是带引号的独立启动器绝对路径及 `--task-manager`。不修改其他值、键权限或系统可执行文件；发现已有 Debugger（包括空值）、UseFilter 或子项时拒绝启用。

IFEO 会把调试器前缀加入原启动命令，因此按程序名影响整台电脑，不局限于 Ctrl+Shift+Esc，也不能靠普通启动一次 taskmgr.exe 绕过。参见 Microsoft 的 [IFEO 命令行说明](https://devblogs.microsoft.com/oldnewthing/20070702-00/?p=26193/)。Windows 11 上该注册表分支在 WOW64 视图之间共享，不另写 Wow6432Node，见 [WOW64 注册表规则](https://learn.microsoft.com/en-us/windows/win32/winprog64/shared-registry-keys)。

启动器与独立恢复程序从 Argus 发布程序内嵌的字节安装到受保护的 `Argus Privileged` 目录，不从相邻的可写 sidecar 加载。界面也复制为该目录中的独立版本文件，移动原免安装版不会留下悬空的 IFEO 路径。目录与文件沿用特权服务的管理员和 SYSTEM 写入权限校验。

启动器只为授权账户尝试启动 Argus；其他账户直接尝试原生任务管理器。Argus 在调用者会话中以标准权限运行：未提升的启动器直接创建界面；提升后的启动器（例如从管理员身份的命令提示符运行 `taskmgr`）把界面创建为桌面外壳（资源管理器）的子进程（`PROC_THREAD_ATTRIBUTE_PARENT_PROCESS`），界面继承外壳的标准令牌；找不到外壳或外壳不属于同一账户时回到原生路径。账户没有拆分令牌（关闭 UAC、内置 Administrator 账户）时只有一种令牌，界面与平时一样以它运行。界面的环境变量按当前账户重新生成，不沿用创建者的环境。

不使用提升令牌的关联令牌（`TokenLinkedToken`）：没有 SeTcbPrivilege 的进程取到的只是识别级令牌，Windows 拒绝据此创建主令牌（`ERROR_BAD_IMPERSONATION_LEVEL`，在普通权限下对受限令牌的关联令牌实测）；没有拆分令牌的账户则没有关联令牌可取。

开启时的界面自检按发起者 PID、创建时间、账户及会话核对后，把自检进程创建为发起者进程的子进程，继承发起者的令牌，因此 UAC 使用另一管理员凭据也不会把界面开到管理员账户下。这种情况下发起者进程的 DACL 不授予管理员账户任何权限，维护助手启用 SeDebugPrivilege 后再打开它；令牌只需读取用户，管理员组对令牌有查询权限。服务不启动 SYSTEM 权限的交互界面。

界面唤起有独立的就绪握手，进程创建成功不算完成。前端挂载后或收到唤起事件时确认，启动器等待 10 秒，再给显示确认 2 秒。握手使用随机名称、账户 ACL、父进程创建时间及固定启动器路径；父进程退出后，迟到的请求不显示窗口。单实例仍显示已有窗口，不切换为隐藏；超时也不结束已有 Argus。专为此次请求创建、始终未显示的界面实例在 15 秒后退出。

## 开启与恢复记录

1. 锁定专用安装目录，检查授权账户和现有 IFEO 配置。
2. 准备启动器、恢复程序、界面副本和 `taskmgr-recovery.txt` 应急说明。
3. 在管理员维护助手中创建随机名称的无窗口测试程序和它专用的临时 IFEO 条目：普通启动必须被重定向，调试启动必须成功绕过。清理完成后，再以发起者标准权限完成界面就绪检查。任何失败均不写入 taskmgr.exe 的 Debugger。
4. 将 `taskmgr-recovery.json` 的 Prepared 记录写入受保护的新文件、同步并替换；记录原值的存在性、类型与原始字节、本次写入值、账户和界面副本名。第一版拒绝接管已有 Debugger，因此有效原值为不存在。
5. 再读一次当前状态，写入 Debugger、刷新注册表并读回核验，最后将记录改为 Active。

恢复先检查当前值仍与本次写入值完全一致，再记录 Restoring、恢复原值、刷新并核验，最后记录 Restored。实际状态已经是原状态时，恢复是幂等的；第三方修改或不可信备份会中止自动恢复并保留文件。只删除 Debugger 值，不删除整个 taskmgr.exe 键；新建后留下空键不影响 Windows 启动行为。

注册表值与记录文件不是跨资源原子事务。断电发生在任意阶段时，Prepared / Restoring 记录使下次服务启动或恢复操作可以继续还原；恢复记录损坏时须人工核对。安装锁只串行化 Argus 自己的操作，无法锁住同时修改注册表的第三方管理员工具，所以每次写入前后都重新核验，检测到冲突便停止。

临时 IFEO 自检也先保存独立记录 `taskmgr-probe.txt`；恢复或下次自检会清理中断留下的专用条目。它始终使用随机程序名，不临时移除再添加 taskmgr.exe 的替换值。

## 原生回退与应急恢复

原生路径使用系统目录的固定 taskmgr.exe，不执行 IFEO 附带的任意路径或把附带参数转发给 Argus。先以 `DEBUG_ONLY_THIS_PROCESS | CREATE_SUSPENDED` 创建，再设置退出时不结束被调试进程、脱离调试并恢复线程，避免再次进入 IFEO。脱离失败会清理本次新建的进程并报错，不结束其他进程。API 行为见 [DebugActiveProcessStop](https://learn.microsoft.com/en-us/windows/win32/api/debugapi/nf-debugapi-debugactiveprocessstop) 和 [DebugSetProcessKillOnExit](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-debugsetprocesskillonexit)。

此路径不依赖服务、Tauri 或 WebView2。系统策略、令牌限制或文件损坏仍可能使原生启动失败，启动器会提示错误；不能保证已损坏或被删除的启动器自行恢复。

独立恢复程序为受保护目录中的 `argus-taskmgr-recover.exe`，直接运行会请求管理员权限，不要求 Argus 界面或服务可用。如果它也损坏，可从 Win+R 打开管理员注册表编辑器，核对 Debugger 确实指向此安装的启动器，且可信恢复记录的原值不存在，再只删除该 Debugger 值。已有第三方值不得删除；备份缺失时先人工确认归属。

## 更新和卸载

特权服务更新、卸载前必须先完成恢复；冲突、记录损坏或写入失败会阻止继续。更新成功后替换保持关闭，用户可以在设置中重新开启并再次完成自检。这个选择避免更新结束后在无人确认时重新改动系统入口。

NSIS 的卸载前钩子（`src-tauri/installer-hooks.nsh`）先询问是否一并卸载特权服务（卸载服务时同样先恢复），再做恢复检查：优先调用独立恢复程序，缺少该程序时调用 Argus 的早期维护模式；取消授权或恢复失败会停止卸载。升级安装时选择“先卸载再安装”，安装程序会就地运行旧的卸载程序（`$EXEDIR` 等于 `$INSTDIR`），而真正的卸载从 `%TEMP%` 中的副本运行；钩子据此跳过就地卸载的这两步，因为替换所用的文件都在服务目录，不随 GUI 删除。恢复程序及备份会保留在服务目录，避免在恢复过程异常时失去最后的修复入口；仍在运行或旧版本的界面副本也不会被强行删除。

## 代码与验证

`crates/argus-service/src/taskmgr/` 按职责分为状态机、固定注册表适配、启动与令牌处理、前端握手；两个 `src/bin/argus-taskmgr-*.rs` 生成独立程序。Tauri 发布构建先构建这两个程序，再把字节内嵌进 Argus。开发版不会提供启用功能。

服务协议第 4 版只新增无参数的 `RestoreTaskManager`，没有通用写注册表、任意命令或路径接口。开启仍走明确授权的管理员维护助手。恢复失败时允许独立助手重新核验后重试，这个恢复动作按记录幂等。

普通测试使用内存注册表和自己创建的子进程，覆盖备份失败、提交失败回退、中断阶段恢复、重复恢复、第三方冲突、过滤键拒绝、恢复失败保留记录、命令行转义、真实调试创建后的脱离和运行结束，以及指定父进程时的令牌继承（低完整性父进程下创建的子进程同为低完整性，而不是创建者的中完整性）。它们不写入真实 IFEO，也不运行系统任务管理器。

管理员环境仍需验收：临时 IFEO 自检、Ctrl+Shift+Esc 与其他入口、提升后的启动器、服务停止、界面慢启动和无响应、另一账户、另一管理员凭据、关闭 UAC 与内置 Administrator 账户、UAC 取消、文件缺失、更新与卸载中断。只有这些通过才能确认系统替换完整可用。

维护助手出错时，把原因写入服务目录中的 `taskmgr-error.txt`，并注明出错的步骤（准备文件、启动自检、以发起者账户启动界面自检）。发起操作的界面读回原因后显示在设置页并写入日志；助手每次运行前清掉上一次的记录，写不进去时才弹出消息框。启动器没有窗口：没能打开 Argus、改为打开 Windows 任务管理器时，或者开启时的界面自检失败时，它把原因追加到当前账户日志文件夹中的 `taskmgr.log`（超过 256 KB 时重新开始）。
