# 管理员启动

本页说明**管理员运行**的实现：受保护的启动通道与计划任务、权限交接与失败处理、设置与维护，以及从 0.5 及更早版本的迁移。用户侧的说明见[管理员运行](../guide/settings/permissions.md#管理员运行)。

**管理员运行**默认关闭。具有管理员身份的当前 Windows 账户经一次 UAC 确认后，可建立启动授权。特权服务、PawnIO 和系统任务管理器替换分别授权。持久的管理员启动任务仅供发布构建使用。

## 启动通道

启动通道由运行目录中的程序与记录、绑定账户的计划任务组成。管理员启动不依赖特权服务是否运行，也不随服务卸载而取消。

### 运行目录

`argus-service::admin` 管理受保护目录中的 `Program Files\Argus Privileged\runtime\<应用标识>\<账户 SID>`，见[特权服务的受保护目录](privileged-service.md#受保护目录)。目录中有稳定的 `argus-launcher.exe`、界面程序 `argus-admin.exe`、普通启动记录 `launch.json` 和管理员授权记录 `grant.json`，普通账户不能替换这些文件。

界面程序的文件名固定，计划任务的动作因此不随更新改变。更新时界面程序若正在运行，原文件以 `argus-admin.old.exe` 让位，退出后由下一次维护删除。

### 计划任务

计划任务绑定当前账户，以 `InteractiveToken` 和 `HighestAvailable` 运行，见[任务安全上下文](https://learn.microsoft.com/en-us/windows/win32/taskschd/security-contexts-for-running-tasks)。启动器通过 `RunEx` 指定交互会话，见[RunEx 的会话与参数](https://learn.microsoft.com/en-us/windows/win32/api/taskschd/nf-taskschd-iregisteredtask-runex)。

账户有权读取和执行任务，管理员与 SYSTEM 可修改。任务动作指向受保护的 Argus 程序，助手参数仅编码窗口显隐、更新标记和任务管理器就绪握手。

启动任务采用优先级 4，使启动助手使用普通 CPU、I/O 与内存优先级，符合交互应用的启动用途。数值映射见 [Task Scheduler 的 Priority 定义](https://learn.microsoft.com/en-us/windows/win32/taskschd/taskschedulerschema-priority-settingstype-element)。

计划任务将用户 SID 规范化为账户名后，校验仍按用户 SID 进行。裸账户名命中同名计算机或域对象时，使用查询返回的域限定账户名重新解析，并确认结果为用户账户。

### 注册与校验的诊断

授权助手在解析 Shell 文件夹之前初始化 COM 安全，采用 Packet Privacy 与 Impersonate，符合[任务计划程序初始化示例](https://learn.microsoft.com/en-us/windows/win32/taskschd/time-trigger-example--c---)。

注册失败时，助手补充以下只读诊断，保留原注册错误码，不记录任务 XML、参数或账户名：

- XML 校验与现有任务查询的 HRESULT
- 任务状态与支持的架构版本
- COM 初始化结果、提升状态与会话
- 调用者身份是否匹配
- 直接参与操作的程序路径，其中以账户 SID 命名的目录记为 `<SID>`

任务的缓存条目或任务文件丢失后，按名称查不到该任务，名称却仍被占用，同名注册通常以 `ERROR_FILE_NOT_FOUND` 失败。因此，注册失败且查不到任务时，先删除该名称的残留注册再重试一次，此时删除不会丢失可用的任务。仍失败时，设置页提示任务计划程序未能创建启动任务、可能受到安全软件的计划任务防护，原错误码只写入诊断日志。

已有任务的校验失败按启用状态、账户 SID、登录类型、运行级别、动作数量、程序路径和参数分别记录阶段。读取属性或解析账户失败时保留原始错误码，校验不匹配仍返回 `ERROR_INVALID_DATA (13)`。日志仅记录失败阶段与错误码，不记录账户名、SID、任务 XML 或动作参数。

### 登录启动与快捷方式

登录启动仍使用现有的 Run 项和 Windows 的**启动应用**开关，目标改为稳定启动器并带 `--hidden`。普通快捷方式和固定图标使用同一策略，窗口的 AppUserModelID 保持应用标识。

系统任务管理器替换先创建普通权限入口，该入口在创建单实例与主窗口之前按管理员授权路由。常驻快捷键显示已经运行的管理员实例。

授权任务和记录提交后，快捷方式迁移失败保留已生效的授权；不可用的桌面或开始菜单目录按具体步骤记录到诊断日志。

## 权限切换与失败处理

启动请求使用随机名称事件和有界数据。助手核对请求者的 PID、创建时间、账户、会话和完整性级别，拒绝受限令牌。原进程确认并退出后，助手启动目标权限的界面。

已有普通窗口时，管理员副本通过单实例消息提出交接。接收方核对进程的管理员令牌、账户、会话、创建时间和受保护的程序路径后退出。新进程取得单实例锁，再读取设置、启动采样与历史记录并创建窗口。已有管理员窗口时只传递显示和就绪请求。

首帧绘制后确认启动成功。准备失败时保留原界面，目标启动失败时清理本次启动的进程并恢复普通权限界面。自动启动发现任务失效时在设置中提示修复，修复操作重新申请授权。由任务管理器替换启动时可回退到 Windows 任务管理器。

## 设置、引导与维护

关闭授权与开启、安装后维护共用运行目录中的 `install.lock`。其他操作持有该锁时，关闭授权报告失败，可稍后重试。

### 设置与引导

设置分别显示授权状态和当前进程权限。授权是否存在以计划任务为准，运行目录或授权记录异常时仍可关闭授权。账户没有运行目录时不连接任务计划程序；没有授权记录时，任务计划程序不可用不显示为错误。

需要切换权限时，在设置中的准备完成后重启。引导中的授权先保存，在完成或跳过引导并保存引导状态后切换。

### 关闭授权

关闭授权逐级固定真实目录并拒绝目录链接，不依赖目录的所有者与 ACL。锁文件只打开其本身。管理员无法打开锁文件，或锁文件被替换为重解析点、硬链接时，说明目录已被外部修改：关闭授权不经该锁继续，也不打开链接的目标。

关闭授权先删除计划任务，再清理授权记录和旧的界面副本，保留普通启动记录指向的程序；该记录不可信时，保留全部副本。登录启动偏好、设置和历史均保留。普通权限窗口准备失败时，撤销仍生效，当前窗口保留并提示退出后重新打开。

关闭 UAC 等没有分离令牌的管理员账户，没有可切换的普通令牌。这类账户撤销授权后保留账户默认权限，不等待普通权限启动助手；界面仍显示当前进程的实际权限。

### 安装后维护与卸载

安装后钩子更新已有受保护记录和任务动作，不为其他账户新增授权。

卸载先结束界面副本，从任务计划程序枚举并撤销当前应用标识和有效账户 SID 对应的任务，再删除管理员启动文件；运行目录缺失也可撤销任务。

清理使用独立的删除路径：逐级固定真实目录，拒绝目录链接及并发替换，仅删除已知文件名，不使用其中的授权内容，也不修改所有者或 ACL。文件仍被占用时保留失败状态，释放后可重试；未知文件保留，不递归处理目录。

各应用标识共用的 `runtime` 为空时随后删除，受保护目录因此变空时也删除，删除失败不影响卸载。0.5 及更早版本的 `Argus Runtime` 按同样规则清理。普通启动器与任务动作的程序路径不依赖免安装版原位置。

### 受保护副本的更新

手动更新免安装版时，先关闭**管理员运行**并退出，替换文件，再从新版重新开启。发现受保护副本较旧时，新版以普通权限启动，在用户授权后更新受保护副本。

同一版本号的重建按程序内容识别。比较结果按文件路径、大小和修改时间缓存，源程序更换后重新比较。

## 从 0.5 及更早版本迁移

0.5 及更早版本把账户目录放在 `Program Files\Argus Runtime\<应用标识>\<账户 SID>`，界面程序名为 `argus-admin-<GUID>.exe`。新版在新目录没有记录时照常读取旧目录，用于状态、启动器、快捷方式与单实例交接的副本核对；记录只写入新目录。

安装后钩子 `--argus-admin-refresh` 对每个有记录的账户执行维护，开启或修复授权时也一样。迁移按以下顺序进行：

1. 在 `runtime` 下建立账户目录，写入 `argus-admin.exe`、启动器、图标和待提交的授权记录。
2. 计划任务改为启动新目录的 `argus-admin.exe`，写入 `launch.json`，再提交 `grant.json`。
   - 任一步失败时，任务改回原来的程序，新目录中写下的 `launch.json` 删除，记录仍在旧目录。新的界面程序保留，因为未写入磁盘的任务注册可能仍指向它。
   - 旧目录有 `grant.json` 而新目录没有时（迁移在提交授权之前中断），仍读取旧目录，授权不会因断电丢失，下一次维护重新迁移。关闭授权同时删除两处的 `grant.json`。
3. 对 `HKLM\SOFTWARE` 调用 `RegFlushKey`，把整个配置单元连同其中 `Schedule\TaskCache` 的任务注册写入磁盘；写入失败时，旧目录保留到下一次维护。任务计划程序另存于 `System32\Tasks` 的任务文件不由 Argus 写盘。
4. 执行维护的账户就是授权账户时，该账户指向旧启动器的入口改指新启动器，保留名称、参数和**启动应用**中的开关状态。
   - 入口包括桌面、开始菜单、任务栏固定项中指向旧启动器（参数为 `--argus-launch <应用标识>`）的快捷方式，以及当前用户 `Run` 中指向旧启动器的登录启动项。
   - 全部改指成功后，按文件名删除旧目录中的已知文件和空目录；有一项改不了时，按第 5 步保留转发启动器。
5. 安装程序以其他管理员账户或 SYSTEM 运行时，改不了授权账户自己的快捷方式和登录启动项。此时旧目录只保留换成新版的启动器、图标和空的 `install.lock`，转发启动器读取新目录的记录，旧快捷方式与登录启动照常可用。旧目录的所有者或权限不再可信时不写入，旧目录保持原样。
   - 授权账户下次打开 Argus 时，在后台把自己的快捷方式和登录启动项改指新启动器，无需管理员授权。
   - `--argus-close-copies` 只关闭执行安装的账户自己的管理员副本。升级时授权账户仍在运行的旧版副本保留单实例锁：旧版副本退出之前，打开 Argus 仍显示它的窗口；入口在它退出后的下一次打开时改指。
   - 授权账户下一次开启、关闭或修复管理员运行时，或卸载 Argus 时，旧目录随之删除；关闭授权时先把任务的删除写入磁盘，再删除旧目录。

桌面、开始菜单和任务栏固定项以外、指向旧启动器的快捷方式不会改写，旧目录删除后失效，需要重新创建。
