# docs 的代理须知

修改 `docs/` 之前先读[文档规范](development/docs-style.md)：文档的分类、页面结构、行文、格式语义与检查方法都在那里，本文件只列代理容易做错的地方。

## 受众分层

- `README.md`（仓库根目录）：对外公开的介绍，参考典型开源项目：是什么、特性、系统要求、怎么构建、快捷键摘要、文档入口、路线图摘要。保持简短，不放实现细节和测量过程。内部开发细则（提交规范、发布流程、CI）也不写进去，包括文档链接后的说明文字。
- README 的标题 emoji 不要带变体选择符 U+FE0F（如 🛠️、⌨️、🗺️）：GitHub 生成锚点时会保留这个不可见字符，`#-标题` 形式的链接就会失效。
- 更新 README 预览图运行 `node scripts/readme-previews.mjs`。用当前源码构建的窗口，捕获 Windows 11 的激活态 Mica 背景，按名称升序展示模拟应用及其真实图标。四张图共用同一段连续实测的 CPU、内存、磁盘、网络和 GPU 负载，逐张核对中英文与深浅主题。
- README 特性区的六段操作演示由 `node scripts/readme-features.mjs` 生成（绘制代码在 `scripts/lib/feature-demos.mjs`）：每段是只用 CSS 关键帧的独立 SVG，界面文字按键名取自 `locales/`，用无头浏览器按演示所用字体测量后排版。演示涉及的界面文案、菜单或页面结构变化时重新生成，并按语言逐张核对长文案是否截断；演示数据为虚构值，远程地址用文档保留网段。
- 九份 README 内容对应：`README.md` 为简体中文，`README.zh-TW.md` 为繁体中文，`README.en.md`、`README.es.md`、`README.de.md`、`README.ja.md`、`README.ko.md`、`README.fr.md`、`README.ru.md` 分别为英文、西班牙文、德文、日文、韩文、法文和俄文。修改公共内容时同步各版；顶部语言导航互相链接，当前语言加粗，不加“阅读语言”之类的前缀；不设单独的语言说明章节。
- 英文截图（`screenshot-en-*.png`）用测试标识下的英文设置与模拟快照截取，模拟数据里的进程与服务描述随之换成英文。其他语言复用英文截图时注明图片语言；链接到中文 `docs/` 页面时注明。各版保留 `code-signing-policy` 锚点、签名状态、责任人、隐私策略入口和 SignPath 英文致谢原文。
- `docs/`：给用户和开发者看的详细信息。`AGENTS.md`（根目录与各子目录）：只给 AI 代理看的规则与经验。约束代理行为的内容（征得同意的范围、回复里要说明的事项、代理工具的用法）不写进 `docs/`，面向人的说明也不要只写在 `AGENTS.md` 里。

## 改动文档

- 改完运行 `pnpm docs:lint <改动的文件…>`。它同时检查仓库中所有指向 `docs/` 的路径与锚点（README、更新日志、`.github/`、脚本注释和各 `AGENTS.md`），移动页面或改动标题后按提示更新这些引用。
- 更新日志与已发布的 Release 链接到 `docs/` 的锚点（如 `guide/README.md#历史`、`guide/hardware-data.md#消费级硬件兼容范围`），这些链接无法再改：对应标题保留原名；内容移到其他页面时，原页面保留同名标题，用一两句概括并链接到新位置。
- 重写或拆分页面时保留原有的全部事实，只改组织与措辞；发现与代码不符的内容，核对代码后改正，并在回复里说明。
- 不写验收清单，也不写“待验收”“尚未实测”之类的说明：需要用户在特定环境检查的事项直接在回复里告诉用户。
- 代码行为变了（快捷键、设置项、默认值、模块职责、IPC 命令），同步改对应页面；根 README 的特性列表和快捷键表只放最常用的内容。
- 纯文档修改按根目录的验证范围核对差异与链接即可；涉及官网的组件、生成逻辑或页面布局时，再按 `website/AGENTS.md` 验证对应的构建或画面。
