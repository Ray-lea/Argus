# docs 的代理须知

## 受众分层

- `README.md`（仓库根目录）：对外公开的介绍，参考典型开源项目：是什么、特性、系统要求、怎么构建、快捷键摘要、文档入口、路线图摘要。保持简短，不放实现细节和测量过程。内部开发细则（提交规范、发布流程、CI）也不写进去，包括文档链接后的说明文字。
- README 的标题 emoji 不要带变体选择符 U+FE0F（如 🛠️、⌨️、🗺️）：GitHub 生成锚点时会保留这个不可见字符，`#-标题` 形式的链接就会失效。
- 更新 README 预览图运行 `node scripts/readme-previews.mjs`。用当前源码构建的窗口，捕获 Windows 11 的激活态 Mica 背景，按名称升序展示模拟应用及其真实图标。四张图共用同一段连续实测的 CPU、内存、磁盘、网络和 GPU 负载，逐张核对中英文与深浅主题。
- 英文版 `README.en.md` 与 `README.md` 内容对应，改一边要同步另一边；两者顶部的语言切换行互相链接。英文截图（`screenshot-en-*.png`）用测试标识下的英文设置与模拟快照截取，模拟数据里的进程与服务描述会随之换成英文。英文版链接的 `docs/` 页面是中文的，链接处注明。
- `docs/`：给用户和开发者看的详细信息。
- `AGENTS.md`（根目录与各子目录）：只给 AI 代理看的规则与经验。不要把这些内容写进 README 或 docs，也不要把面向人的说明只写在 AGENTS.md 里。

## 结构

- `docs/README.md` 是索引；每个子目录的 `README.md` 是该部分的入口页，并链接本目录下的其他页面。
  - `guide/`：用户可见的功能与操作
  - `development/`：开发环境、命令、构建、性能测量
  - `architecture/`：模块职责与数据流
  - `design/`：设计原则与实现决策（附测量依据）
  - `roadmap.md`、`known-issues.md`
- 新增或移动页面时，同时更新所在目录的 `README.md`、`docs/README.md`，以及根 `README.md` 里受影响的链接。
- 链接一律用相对路径；改完检查所有链接都能解析。

## 写法

- 中文；API、类型、文件和代码标识保持原文，用代码格式。
- 直接陈述结论、事实与操作，用具体依据支撑；精简先否定再转折、刻意纠偏与重复限定。影响操作、安全或数据解释的条件紧贴对应内容说明一次。
- 实测数字注明条件（机器、构建类型、刷新间隔）。结论来自测量；推翻旧结论时直接改正文，不保留错误的说法。
- 文档围绕读者需要组织用法、行为、基线、方法、设计决策及其依据；测量原始记录与逐轮验证过程留在构建产物目录。
- 不写验收清单，也不写“待验收”“尚未实测”之类的说明：需要用户在特定环境检查的事项直接在回复里告诉用户。
- 代码行为变了（快捷键、设置项、默认值、模块职责、IPC 命令），同步改对应页面；根 README 的特性列表和快捷键表只放最常用的内容。
