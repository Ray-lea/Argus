# 已知问题

## 功能限制

- **每核 CPU** 只统计第一个处理器组（不超过 64 个逻辑处理器）。
- **文件占用**合并 Restart Manager 与句柄扫描，已能查到普通进程的当前目录及硬链接引用。受保护进程（例如某些系统 DLL 的使用者）仍可能无法访问；句柄已经关闭的映射也不保证检出。句柄扫描不跟随符号链接、目录联接、网络或 SUBST 路径；超时、权限不足、文件状态变化或扫描上限都会使结果不完整，界面会提示。
- **管理员权限**：多数服务的启停、所有用户启动项的启用 / 禁用需要管理员权限；没有权限时界面会明确提示。
- **每进程网络流量**依靠 ETW 事件跟踪会话，可由管理员权限的 Argus 或已授权的特权服务提供；两者都不可用时隐藏网络列。服务数据通过后台读取，通常晚一个刷新周期。GUI 的本地会话在进程被强制结束后会残留，下次启动时清理；服务会话在没有读取请求 15 秒后关闭，服务本身被强制结束时则在下次服务启动时清理。
- **历史记录**每 5 秒只保存 CPU、内存、I/O、GPU、网络各自占用最高的几个进程（每帧最多 21 个），其余进程不在历史里；每进程网络流量只在本地或服务采集可用时记录。
- **CPU 温度与电压**：默认使用 ACPI 热区；启用内核传感器后可通过特权服务和官方 PawnIO 读取内部传感器。AMD CCD 温度不是每核温度，旧处理器 Tctl 不是实际结温，VID 是请求电压。Zen 4 / Zen 5 不使用旧 SVI2 电压换算。不支持的型号、缺少接口或驱动受系统策略限制时，相应指标仍不可用。
- **功耗**：CPU 优先使用 Windows Energy Meter，内核传感器补充封装功耗。GPU 支持 NVML、ADL2、IGCL，按驱动能力提供板卡、芯片或 GPU 电源域读数并标明来源；老型号不保证提供瓦数。AMD 的功耗调节百分比不作为瓦数上限。

更多见[硬件数据的来源与限制](guide/hardware-data.md)。

## 运行

- 刚启动的前 20 秒左右，WebView2 首次渲染与图标解码的开销较高，之后回落到[性能基线](development/performance.md)的数值。
- 单实例插件的限制：如果旧进程被强制结束后几秒内立即重新启动，可能出现两个实例。正常退出不受影响。

## 开发

- 部分杀毒软件的脚本扫描（AMSI）会让 Windows PowerShell 偶发崩溃。`start.bat` 会重试，仍失败时跳过启动前的清理并继续启动，不影响开发。
