# 已知问题

## 功能限制

- **文件占用查询**合并 Restart Manager 与句柄扫描。受保护进程、已关闭句柄的映射、扫描超时或并发文件变化都可能影响结果。句柄扫描的路径范围和界面提示见[文件占用](guide/README.md#文件占用)。
- **服务与启动项**的操作权限取决于目标。管理多数系统服务或修改所有用户的启动项需要管理员权限。可交给特权服务执行的操作见[权限](guide/settings.md#权限)。
- **任务管理器替换**启动特权服务目录中的 Argus 副本。手动更换免安装版或安装器更新服务失败后，在新版的“设置 → 权限”中单击“更新服务”，让 Ctrl+Shift+Esc 打开新副本。更换免安装程序前先从托盘退出旧版。
- **安全软件的风险提示**：任务管理器替换通过 `taskmgr.exe` 的 IFEO `Debugger` 值把启动转给 Argus，部分恶意程序也使用这一机制，卡巴斯基（`HEUR:Trojan.Multi.IfeoDeb.a`）、Malwarebytes（`RiskWare.IFEOHijack`）等因此可能报告该注册表值，并在之后的扫描中反复提示。检测对象是注册表值本身，它只在开启替换时写入一次，内容固定指向 `Argus Privileged` 中的 `argus-taskmgr-launcher.exe`；按文件、文件夹或受信任程序添加的排除不覆盖这类检测。可向安全软件厂商提交误报，或在“设置 → 权限”中恢复 Windows 任务管理器，改用全局快捷键（默认 Ctrl+Alt+Esc）打开 Argus，见[替换系统任务管理器](guide/settings.md#替换系统任务管理器)。
- **安装位置之外的文件**：特权服务、管理员运行与内核传感器的程序无需每次确认即以 SYSTEM 或管理员身份运行，因此无论 Argus 安装在哪里，它们都放在只有管理员能修改的 Program Files（`Argus Privileged` 与共享的 `PawnIO` 驱动），仅在开启对应功能后创建；0.5 及更早版本另有的 `Argus Runtime`、`Argus Sensor Setup` 在升级后移入 `Argus Privileged`。开启管理员运行或经任务管理器替换打开 Argus 时，运行的是这些副本。安装到 Program Files 以外时，安装程序把安装文件夹设为只有管理员能修改，无法这样保护的位置在安装前说明原因，见[权限](guide/settings.md#权限)。
- **每进程网络流量**需要可用的本地 ETW 会话或已授权的特权服务。服务读数经后台传递，通常比本地采样晚一个刷新周期。两种来源均不可用时，界面隐藏网络列。
- **历史记录**按 CPU、内存、I/O、磁盘、GPU 和网络占用保存每个时刻最忙的进程，默认每帧约 20 个，可在“设置 → 数据与历史”中改为约 40 个或全部活跃进程。查找当前运行的其他进程请使用进程页。记录间隔见[历史](guide/README.md#历史)。
- **全局快捷键**按一组修饰键和一个主键匹配，左右修饰键视为同一键。录制规则和保留组合见[设置](guide/settings.md#快捷键)。
- **组策略禁用小组件后的空白**：Argus 按任务栏设置中的“小组件”开关（`TaskbarDa`）和小组件应用是否安装，判断 Windows 11 任务栏上有无小组件按钮，并为按钮让出约 160 像素（100% 缩放时）：任务栏监控位于“任务栏左侧”时从按钮右侧开始，任务栏按钮靠左时与托盘之间留出按钮的位置。组策略“允许小组件”（计算机配置 → 管理模板 → Windows 组件 → 小组件，对应 `HKLM\SOFTWARE\Policies\Microsoft\Dsh` 的 `AllowNewsAndInterests`）设为“已禁用”时，任务栏隐藏该按钮，但不改动这一开关，开关同时变为不可更改；禁用前开关为开启时，Argus 仍为按钮让出位置，该处留下空白。可先将该策略设为“已启用”，在“设置 → 个性化 → 任务栏”中关闭“小组件”，再将策略改回“已禁用”，任务栏监控在下一次刷新时移到原按钮的位置。任务栏监控的位置见[任务栏监控](guide/resident-mode.md#任务栏监控)。
- **硬件传感器**的覆盖范围取决于型号、固件和驱动。AMD 每核温度需要已映射的 SMU 字段，主板风扇以硬件通道编号显示。读数来源和适用型号见[硬件数据](guide/hardware-data.md)。
- **厂商存储驱动管理的磁盘**不显示温度。由 Intel RST／VMD、厂商 NVMe 或 RAID 驱动管理的 NVMe 磁盘在磁盘详情中不显示 NVMe 健康日志与 PCIe 链路，健康状况卡片显示“设备或驱动未提供可读取的磁盘健康信息”。温度与 NVMe 健康信息的查询由存储控制器的驱动直接处理，部分厂商驱动收到后不返回、使整机停止响应，或写坏内核内存、导致系统蓝屏，因此 Argus 只向 Windows 自带的存储驱动（`stornvme`、`storahci`、`atapi`）发送这两类查询。型号、序列号、容量、卷与读写性能照常显示。诊断日志的 `disk: N; bus=…; storage driver=…` 一行列出每块磁盘所用的驱动；开放计划见[路线图](roadmap.md)。
