# 已知问题

## 功能限制

- **每核 CPU** 只统计第一个处理器组（不超过 64 个逻辑处理器）。
- **文件占用**合并 Restart Manager 与句柄扫描，已能查到普通进程的当前目录及硬链接引用。受保护进程（例如某些系统 DLL 的使用者）仍可能无法访问；句柄已经关闭的映射也不保证检出。句柄扫描不跟随符号链接、目录联接、网络或 SUBST 路径；超时、权限不足、文件状态变化或扫描上限都会使结果不完整，界面会提示。当前已验证普通权限的自有进程，SYSTEM 服务场景仍待管理员环境验收。
- **管理员权限**：多数服务的启停、所有用户启动项的启用 / 禁用需要管理员权限；没有权限时界面会明确提示。
- **每进程网络流量**依靠 ETW 事件跟踪会话，可由管理员权限的 Argus 或已授权的特权服务提供；两者都不可用时隐藏网络列。服务数据通过后台读取，通常晚一个刷新周期。GUI 的本地会话在进程被强制结束后会残留，下次启动时清理；服务会话在没有读取请求 15 秒后关闭，服务本身被强制结束时则在下次服务启动时清理。真实管理员环境的 ETW 验证仍待完成。
- **历史记录**每 5 秒只保存 CPU、内存、I/O、GPU、网络各自占用最高的几个进程（每帧最多 21 个），其余进程不在历史里；每进程网络流量只在本地或服务采集可用时记录。
- **CPU 温度**来自 ACPI 热区（`Thermal Zone Information` 计数器），多数笔记本上它跟随 CPU 封装温度，台式机主板上可能只是一个固定值或不存在。每核温度和 CPU 电压在处理器的 MSR 寄存器里，Windows 只允许内核驱动读取，目前不提供。
- **功耗**来自 `Energy Meter` 计数器（Intel RAPL），需要较新的 Intel 平台；AMD 与部分台式机没有。GPU 电压取决于显卡驱动，NVIDIA 不提供。

更多见[硬件数据的来源与限制](guide/hardware-data.md)。

## 运行

- 刚启动的前 20 秒左右，WebView2 首次渲染与图标解码的开销较高，之后回落到[性能基线](development/performance.md)的数值。
- 单实例插件的限制：如果旧进程被强制结束后几秒内立即重新启动，可能出现两个实例。正常退出不受影响。

## 开发

- 部分杀毒软件的脚本扫描（AMSI）会让 Windows PowerShell 偶发崩溃。`start.bat` 会重试，仍失败时跳过启动前的清理并继续启动，不影响开发。
