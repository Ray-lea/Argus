# 窗口外观

窗口使用 GPUI Kit 的 `TitleBar` 和 Windows 原生窗口管理。Windows 11 22H2（内部版本 22621）及以上默认使用 Mica；Windows 11 21H2、Windows 10 或系统版本读取失败时使用不透明背景。云母能力判定与渲染器使用的 `DWMWA_SYSTEMBACKDROP_TYPE` 保持相同版本边界，避免在背景接口不可用时留下透明表面。窗口主题与界面色板同步，颜色定义见[主题配置](../../resources/theme.json)。

Windows 启动参数 `--opaque-window` 选用绑定到 HWND 的不透明交换链，由 Argus 绘制主题底色。支持云母背景的系统默认保留该材质。两种窗口均在显示前将曲线填充与底色混合。

图形设备异常后的恢复先复制窗口列表，释放列表锁后再同步通知界面重建渲染资源并重绘，允许恢复期间创建或关闭窗口。诊断日志记录设备丢失错误码、恢复开始、替代设备创建与窗口恢复完成，便于定位中断阶段。

默认启动尺寸与最小尺寸来自[应用配置](../../resources/app.json)，分别为 1000×680 和 640×480。已有窗口位置记录时沿用上次保存的尺寸。主显示器的可用区域（不含任务栏）小于最小尺寸时，最小尺寸以可用区域为限。隐藏启动时，平台层按 DPI 校准初始客户区并保留当前桌面焦点。拖动、缩放、系统按钮和命中测试由原生框架处理。

原生窗口消息驱动采样节拍和曲线调度。最小化或隐藏到托盘时暂停持续绘制，恢复时请求新快照。主题、DPI 和尺寸变化使用目标窗口捕获验证，方法见[性能测量](../development/performance.md)。

主动激活窗口时，如有独立的置顶窗口覆盖主窗口中心且遮挡面积达到三分之一，Argus 临时进入置顶层并移至前方。检测只读取窗口属性，不向对方发送同步消息；对方停止处理消息时仍可执行。失去激活或隐藏后恢复普通层级；切换到其他普通窗口时，将 Argus 放到新激活窗口之后，保留该窗口的前后顺序。原本已经置顶的窗口保持原有状态。小型提示和主窗口自身拥有的弹窗保持原有层级。

窗口改变尺寸时，平台层在 `WM_NCCALCSIZE` 中按即将生效的客户区绘制并提交一帧，之后系统才应用新尺寸。DWM 在该消息返回后的下一次合成即显示新尺寸，而 `WM_SIZE` 要到 `SetWindowPos` 结束时才到达，在跨进程缩放的测量中晚 4–13 ms；等到 `WM_SIZE` 再绘制，新尺寸会配着旧内容显示两到三次刷新，露出的边条是窗口底色，标题栏按钮停在原处。165 Hz 显示器、性能页上各缩放 32 次的测量：新尺寸显示旧内容的时间，发行构建由平均 10.0 ms（最长 18.7 ms）降至 2.3 ms，20 次没有旧画面；开发构建由 12.3 ms 降至 1.6 ms，24 次没有旧画面；其余各为一次刷新。剩余的一次刷新来自 DWM：它有时比新尺寸晚一次合成才显示已提交的帧。在返回前等待 GPU 完成不能减少这种情况；等待下一次合成时钟或改用同步间隔 0 提交，会让新内容先于新尺寸显示一次刷新，两类合计不比现在少。

菜单、下拉列表、悬浮提示与通知通过背景和边框区分层级，统一关闭投影；对话框使用遮罩和投影。部分 NVIDIA 显示环境在半透明页面上绘制浮层投影时会出现亮色光晕，关闭投影可避开该现象。普通及换行提示共用 `widgets::tooltip_text`，在此覆盖组件库的默认阴影。

## 按区域使用 ClearType（暂缓）

默认云母窗口的阅读区使用半透明底色和校准后的灰阶文字。整窗实色模式可按系统设置使用 RGB 子像素抗锯齿。当前实现见[原生界面](../architecture/frontend.md#缩放与排版)。

备选方案在公共渲染器内为同一字形缓存 RGB 和灰阶覆盖率。绘字时，若同一绘制表面已有完全不透明的底色覆盖可见字形，且文字与设备像素对齐，则采用 RGB。透出云母、涉及圆角边缘、淡入或缩放的文字采用灰阶。重放缓存时根据当时的背景、裁剪和变换重新判断。

原型通过给进程表、性能详情、历史列表和设置卡片铺设主题实色来扩大 RGB 的覆盖范围。这些区域也随之遮住了云母，与当前保留材质层次的外观要求冲突，方案暂缓。以后若重新评估，优先从已有实色底的菜单和弹窗入手，保持主要阅读区的材质。
