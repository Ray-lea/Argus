# 窗口外观

窗口使用 GPUI Kit 的 `TitleBar` 和 Windows 原生窗口管理。本页说明窗口的材质、标题栏、尺寸、绘制节拍、层级与浮层的设计取舍及实测依据。

## 材质与背景

Windows 11 22H2（内部版本 22621）及以上默认使用 Mica；Windows 11 21H2、Windows 10 或系统版本读取失败时，使用不透明背景。云母能力的判定与渲染器使用的 `DWMWA_SYSTEMBACKDROP_TYPE` 保持相同的版本边界，避免在背景接口不可用时留下透明表面。窗口主题与界面色板同步，颜色定义见[主题配置](../../resources/theme.json)。

Windows 启动参数 `--opaque-window` 选用绑定到 HWND 的不透明交换链，由 Argus 绘制主题底色。支持云母背景的系统默认保留该材质。两种窗口均在显示前将曲线填充与底色混合。

## 图形设备与硬件加速

图形设备异常后的恢复先复制窗口列表，释放列表锁后再同步通知界面重建渲染资源并重绘，允许恢复期间创建或关闭窗口。诊断日志记录设备丢失错误码、恢复开始、替代设备创建与窗口恢复完成，便于定位中断阶段。

**硬件加速**设置决定渲染设备建在哪个适配器上。开启时，按系统的适配器顺序选择第一个可用的 GPU。关闭时，选择带软件标记的适配器（Microsoft 基本呈现驱动程序，即 WARP），由 CPU 执行同一套 Direct3D 11 绘制；该适配器不可用时，仍按原顺序选择。

设置在创建窗口前读取。运行中切换时，帧时钟线程发现当前设备与设置不符，即按上述恢复流程换用新设备，主窗口与托盘浮窗一并重建渲染资源并重绘。原设备仍然有效，因此省去设备丢失后的两段等待。

可见的窗口保留原设备的合成目标与最后一帧，待新设备提交第一帧后再换到新的交换链，切换期间不出现空白画面。隐藏或最小化的窗口、`--opaque-window` 的窗口先释放原设备的资源。

软件渲染设备同样使用曲线合成图层，见[软件渲染时的合成](charts.md#软件渲染时的合成)。诊断日志的启动记录包含 `hardware_acceleration`，适配器记录包含 `software`。

## 标题栏与页面栏

按钮按作用范围分开放置：

- **标题栏**：只放标识、当前页面的搜索框和窗口按钮。
- **页面栏**：放页面控件与**更多操作**菜单。
- **状态栏**：暂停与刷新频率放在显示刷新状态的位置，更新提示由版本徽章显示。

分开放置的原因是：按钮集中在标题栏时，拖动区域会被切成碎片，窗口变窄时控件和搜索框还要分行。

### 标题栏与窗口按钮

标题栏高 48 px。搜索框占窗口宽度的 30%，限于占位文字宽度与 480 px 之间；窗口越窄，留出的拖动区域越多。

窗口按钮按 Windows 系统标题栏按钮的尺寸绘制，每个 46×32 px，贴住窗口右上角（`frontend/caption.rs`）。从左到右依次为**置顶显示**、**最小化**、**最大化**（最大化后为**还原**）与**关闭**。

后三个按钮注册为原生按钮区域（`WindowControlArea::Min`、`Max`、`Close`），由系统按自身的按钮命中，因此最大化按钮保留贴靠布局。**置顶显示**是客户区的普通控件。

按钮下方余下的 16 px 与标题栏的其余部分注册为拖动区域（`WindowControlArea::Drag`），双击最大化。

### 页面栏的紧凑级别

页面栏在顶部导航时位于标签右侧，侧边导航时位于页面顶部。标签或页面名称与控件之间至少保留 16 px 空白，同样注册为拖动区域。

空间不足时，页面栏依次进入以下紧凑级别：

1. 顶部导航的标签只显示图标。
2. 仍放不下时，页面控件移到下一行。
3. 最后才让标签换行。

紧凑级别按页面栏的实际空间判断（`fit_toolbar`），不按固定的窗口宽度，因此控件较多的页面更早收为图标。

标签在文字与图标之间形变：宽度按 250 ms 的缓动曲线变化，文字按时间先淡出，图标随后淡入。形变期间标签不换行，放不下的部分在拖动区之前裁去，页面控件留在原位。

## 窗口尺寸与恢复

默认启动尺寸与最小尺寸来自[应用配置](../../resources/app.json)，分别为 1000×680 和 640×480。已有窗口位置记录时，沿用上次保存的尺寸。主显示器的可用区域（不含任务栏）小于最小尺寸时，最小尺寸以可用区域为限。隐藏启动时，平台层按 DPI 校准初始客户区，并保留当前桌面焦点。拖动、缩放、系统按钮和命中测试由原生框架处理。

恢复窗口位置或最大化状态时，原生尺寸通知可能在界面更新内同步到达。此时保留并合并通知，待更新结束后读取最新的客户区尺寸和缩放比例，重新布局并绘制完整窗口；正常拖动缩放仍同步更新。

从任务管理器替换入口冷启动时，主窗口先隐藏创建，再恢复保存的位置。恢复最大化通过不激活的最小化与还原完成；还原时按实际客户区更新绘图缓冲区，尺寸相同时复用已有缓冲区，确保布局与绘制范围一致。

## 激活与置顶

通过 Ctrl+Shift+Esc 或任务栏菜单打开任务管理器时，替换启动器在界面就绪后，将前台激活权交给实际持有主窗口的 Argus 进程。冷启动和唤回已有窗口使用同一流程。启用替换时的就绪检查保持静默。

主动激活窗口时，如有独立的置顶窗口覆盖主窗口中心，且遮挡面积达到三分之一，Argus 临时进入置顶层并移至前方。检测只读取窗口属性，不向对方发送同步消息；对方停止处理消息时仍可执行。

失去激活或隐藏后，Argus 恢复普通层级；切换到其他普通窗口时，将 Argus 放到新激活窗口之后，保留该窗口的前后顺序。原本已经置顶的 Argus 窗口保持原有状态。小型提示和主窗口自身拥有的弹窗保持原有层级。

**置顶显示**把主窗口放入置顶层（`activation::keep_on_top`），偏好 `alwaysOnTop` 在窗口创建后应用。它同时结束正在进行的临时置顶，之后失去激活或隐藏都不再恢复普通层级；关闭后窗口回到普通层级，激活时的临时置顶照常生效。

测试实例只保存该偏好，不改变窗口层级：置于最底层的测试窗口一旦置顶，会盖住正在使用的桌面。

## 帧时钟与绘制

原生窗口消息驱动采样节拍和曲线调度。最小化或隐藏到托盘时暂停持续绘制，恢复时请求新快照。

帧时钟在下一次垂直同步时，只使请求了新帧的窗口失效：有视图待重绘、动画正在播放，或有尚未呈现的画面。内容不变的可见窗口不再随每次刷新收到 `WM_PAINT`，帧时钟线程随之休眠，仅每秒检查一次设备状态。正在绘制的窗口在绘制期间经过垂直同步时仍会失效，因此超过一次刷新的帧结束后立即开始下一帧。

### 隐藏窗口的绘制

已隐藏的窗口收到 `WM_PAINT` 时，只用 `BeginPaint` / `EndPaint` 确认，不绘制画面，显示时再绘制。

窗口淡出后恢复不透明度，会给已隐藏的窗口留下待绘区域。`ValidateRect` 对隐藏窗口返回成功，但不清除该区域，系统在消息队列空闲时反复生成 `WM_PAINT`，界面线程无法休眠。

在 i5-13500HX、发行构建、后台采样间隔 5 秒的测试实例中，经关闭按钮隐藏到托盘后，界面线程曾因此持续占用约 0.84 个核心，最小化不受影响。改用上述确认方式后，托盘与最小化的进程 CPU 时间同为每秒约 10 ms，隐藏期间不提交画面，隐藏满设定时长后归还的内存也不再被重新占用。

### 改变尺寸时的绘制

窗口改变尺寸时，平台层在 `WM_NCCALCSIZE` 中按即将生效的客户区绘制并提交一帧，之后系统才应用新尺寸。

DWM 在该消息返回后的下一次合成即显示新尺寸，而 `WM_SIZE` 要到 `SetWindowPos` 结束时才到达；在跨进程缩放的测量中，`WM_SIZE` 晚 4–13 ms。等到 `WM_SIZE` 再绘制，新尺寸会配着旧内容显示两到三次刷新：露出的边条是窗口底色，标题栏按钮停在原处。

在 165 Hz 显示器的**性能**页上各缩放 32 次，测量新尺寸显示旧内容的时间：发行构建由平均 10.0 ms（最长 18.7 ms）降至 2.3 ms，20 次没有旧画面；开发构建由 12.3 ms 降至 1.6 ms，24 次没有旧画面。其余各次的旧画面为一次刷新。

剩余的一次刷新来自 DWM：它有时比新尺寸晚一次合成才显示已提交的帧。在返回前等待 GPU 完成，不能减少这种情况。等待下一次合成时钟或改用同步间隔 0 提交，会让新内容先于新尺寸显示一次刷新，两类合计不比现在少。

## 浮层与投影

菜单、下拉列表、悬浮提示与通知通过背景和边框区分层级，统一关闭投影；对话框使用遮罩和投影。普通及换行提示共用 `widgets::tooltip_text`，在此覆盖组件库的默认阴影。

部分 NVIDIA 显示环境在半透明页面上绘制浮层投影时会出现亮色光晕，关闭投影可避开该现象。光晕在 RTX 4080 SUPER、4K、150% 缩放、HDR 关闭时观察到，启动截图工具后消失。

菜单与子菜单关闭时直接消失。下拉列表打开时以裁剪从控件一侧展开（167 ms，减速），不做淡入；关闭时朝弹出的一侧裁剪收起（83 ms，匀速），不做淡出。淡出期间整块浮层是半透明的，在同样的环境里会整块变亮，表现为关闭瞬间的闪白。

## 对话框遮罩

云母窗口在 167 ms 内线性渐变遮罩暗度。渐变期间，Windows 渲染器将页面绘入一张预乘 Alpha 表面，把遮罩和对话框绘入另一张表面，交给 DirectComposition 一起呈现。卡片在底层保留自己的透明度。关闭最后一个面板时，面板与遮罩同时开始淡出。面板在 100 ms 内线性淡出后移除，遮罩的 167 ms 渐变随后继续，直至背景恢复。渐变结束后恢复常规绘制。

面板的缩放时序见[原生界面](../architecture/frontend.md#对话框与输入)，分层实现见 [Windows 渲染补丁](../../vendor/gpui-pre-windows/ARGUS-PATCHES.md)。

嵌套面板共用遮罩。关闭上层面板时，留在底下的面板保持原有暗度。渐变中途反向开关时，遮罩从当前暗度反向过渡。实色窗口直接在页面上绘制渐变。云母窗口缺少分层合成时使用固定遮罩，最后一个面板消失时恢复亮度。关闭**界面动画**后，面板和遮罩立即出现和消失。

遮罩期间窗口按钮仍可操作：图标保持原有亮度，按钮底色与标题栏一同变暗。

深色主题的普通卡片在云母上叠加 3.5% 白色（主题配置中的 `layer`），曲线绘图区使用实色底。v0.6.0 在同一表面绘制遮罩与卡片。在 NVIDIA GeForce RTX 4080 SUPER 上，v0.6.0 使用默认交换链或 `ARGUS_GPUI_COMPOSED_PRESENT=1` 合成位图时都能复现闪白，实色窗口中卡片正常恢复亮度。

锁定曝光的外拍记录到**进程**页与**性能**页磁盘视图的卡片短暂亮过静止画面，窗口捕获中的灰度则单调恢复。在同一显示器的**关于**页反复关闭**运行新任务**时，v0.6.0 的卡片闪白；固定遮罩消除了闪白，分层遮罩平滑渐亮且未见闪白。复核时，同时观察卡片内部与相邻的空白云母区域。

## 按区域使用 ClearType 的方案

默认云母窗口的阅读区使用半透明底色和校准后的灰阶文字，整窗实色模式可按系统设置使用 RGB 子像素抗锯齿，当前实现见[原生界面](../architecture/frontend.md#缩放与排版)。在云母窗口中按区域使用 RGB 的方案已有原型，目前暂缓。

备选方案在公共渲染器内为同一字形缓存 RGB 和灰阶覆盖率。绘字时，若同一绘制表面已有完全不透明的底色覆盖可见字形，且文字与设备像素对齐，则采用 RGB；透出云母、涉及圆角边缘、淡入或缩放的文字采用灰阶。重放缓存时，根据当时的背景、裁剪和变换重新判断。

原型通过给进程表、性能详情、历史列表和设置卡片铺设主题实色，扩大了 RGB 的覆盖范围。这些区域也随之遮住了云母，与当前保留材质层次的外观要求冲突，因此方案暂缓。以后若重新评估，优先从已有实色底的菜单和弹窗入手，保持主要阅读区的材质。
