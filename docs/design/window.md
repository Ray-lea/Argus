# 窗口外观

## Mica 背景

窗口不使用 Tauri 的 `transparent: true`。它靠旧版 `DwmEnableBlurBehindWindow` 让整个窗口按透明窗口合成，拖动时每次移动都更贵：模拟拖动测得超过一帧（165 Hz）的移动占 12–19%，普通 Win32 窗口为 8–10%。

现在由 `windowEffects` 提供 Mica，再用 `DwmExtendFrameIntoClientArea` 把它延伸到客户区，只让 WebView 背景透明（`backgroundColor: #00000000`）。窗口本身保持不透明，拖动开销与普通窗口持平，外观不变。实现在 `src-tauri/src/shell.rs` 的 `extend_backdrop`。

## 调整大小时的斜线

**现象**：调整窗口大小（尤其是慢慢放大）时，客户区对角线上偶尔闪过一条亮线。

**原因**：Windows 11 会把窗口裁成圆角。WebView2 把页面画在一个半透明的子表面上（Chromium 的分层输出窗口 `Intermediate D3D Window`），它伸进了窗口底部的两个圆角。窗口尺寸变化时，DWM 处理圆角裁剪的快速路径偶尔会把这种表面沿客户区对角线多混合两到三次，于是闪出一条亮线。画面本身没有被拉伸：出现亮线的帧里，固定间距的竖条纹位置与前后帧完全相同。

**排查**：在只含 WebView2 的最小窗口里同样能复现。逐项对比：

| 条件 | 亮线 |
|---|---|
| 圆角，WebView 铺满客户区 | 出现 |
| 窗口改成直角 | 消失 |
| WebView 底部留边 9 像素以上 | 消失 |
| 底部只留 1–6 像素 | 出现 |
| WebView 的可见区域不是矩形（例如只少左上角 1 个像素） | 消失 |
| 只裁掉圆角本来就藏住的像素（例如底角 1 像素） | 仍有少量 |
| 不把 Mica 延伸到客户区 | 出现 |
| 没有 WebView 的普通窗口，铺满半透明内容 | 不出现 |

**修复**：这条快速路径只用于可见区域是普通矩形的子窗口。所以窗口尺寸一开始变化（`WM_WINDOWPOSCHANGING`，拖动、贴靠、最大化、改 DPI 都经过这里），Argus 就给 WebView 的容器窗口设置一个只少了左上角 1 个像素的区域：那里是透明的页面背景，Mica 照常透出。DWM 改走通用路径后，整个窗口只有圆角抗锯齿边缘的几个像素差几级亮度（最大 12/255）。通用路径每帧多一点合成开销（录制状态下 DWM 的 GPU 占用约 1.1% → 1.6%），所以尺寸停止变化 300 毫秒后撤掉区域，平时不付出这份开销。实现在 `src-tauri/src/shell.rs` 的 `guard_resize_seam`。

把 WebView 底色换成不透明、或者让页面底部留出 9 像素，同样能消除亮线，但会改变外观（拖动时失去 Mica，或底部多一条空白），所以没有采用。

**验证**：用 Windows.Graphics.Capture 录制窗口，逐帧检查客户区对角线（亮线总在这条线上），每秒约 50 帧，与调整大小时窗口内容变化的频率相当。不设区域时每次录制有 32–48 帧出现亮线；设置后为 0，包括从左边缘拖动和快速拖动。常速拖动的录制包含区域加上和撤掉的时刻，相邻帧的整体亮度变化最大 0.04/255，没有闪烁。
